# Дело — roadmap

Статус: исторический предварительный черновик. Актуальные требования — SPEC.md; этот roadmap будет переписан после Architecture. Указанные ниже стек, модель и уступки по материалу не являются текущими решениями. Полная реализация ещё не начата.

## Идея

Бесплатный локальный планировщик для Windows: задачи постоянно под рукой, новую мысль можно записать из любого приложения за несколько секунд. Без аккаунтов, подписок, рекламы и обязательных полей кроме текста задачи.

Основное устройство: Windows 11, экран 1920×1200. Публичная сборка должна работать без установленной среды разработки.

## Принципы интерфейса

- Название: «Дело», каталог и предварительное имя репозитория: Delo.
- Направление: эстетика Apple Liquid Glass — прозрачность, размытие, мягкие блики, качественная типографика и сдержанная анимация.
- Читаемость задач важнее прозрачности. Проверяем светлые, тёмные и пёстрые обои.
- Один компактный виджет, очевидные действия, минимум настроек.
- Учитываем масштабирование Windows, клавиатуру, контрастность и отключение анимации.
- Стекло адаптируем к возможностям Windows; точное воспроизведение материалов Apple не является критерием готовности.

## Первая публичная версия

- Добавление задачи: текст → Enter, дата необязательна.
- Добавление непосредственно в виджете и через отдельную компактную строку по глобальной горячей клавише.
- Предварительные сочетания: Ctrl+Alt+Space — показать/скрыть список; Ctrl+Alt+N — быстрый ввод. Обрабатываем конфликт регистрации сочетания.
- Группы: просроченные, сегодня, ближайшие, без срока. Просрочка выделяется цветом и текстом.
- Простые даты в конце ввода: сегодня, завтра, явная календарная дата. Перед сохранением показываем распознанный срок; конкретный словарь зависит от выбранных языков.
- Выполнение одним кликом, исправление текста и срока, удаление с возможностью отмены.
- Выполненные задачи показываются зачёркнутыми до конца локального календарного дня, затем уходят в архив. Их можно восстановить.
- Необязательный секундомер задачи: запуск, пауза, сохранение накопленного времени. Предварительно одновременно работает один секундомер.
- Настоящий виджет рабочего стола: остаётся видимым после Win+D. Перемещение, сохранение положения и переключение закрепления поверх окон.
- Значок в трее, отсутствие постоянной кнопки в панели задач. Закрытие скрывает окно; выход доступен в трее.
- Автозапуск по выбору пользователя.
- Локальное сохранение, восстановление после перезапуска, резервная копия данных.

## Этап 1. Согласовать продукт

Результат: утверждённые границы первой версии и ответы на вопросы ниже.

Критерий завершения: однозначно описаны режим рабочего стола, языки и судьба выполненных задач. Остальные небольшие UX-решения оформляются в техническом плане с разумными значениями по умолчанию.

## Этап 2. Утвердить визуальное направление

Подготовить макет основного виджета и быстрого ввода: пустой список, реальные задачи, длинный текст, просрочка, работающий секундомер, закреплённое состояние.

Проверить на светлом и тёмном фоне. Согласовать внешний вид до полной реализации.

Результат: выбранный макет, размеры, цвета, типографика, состояния элементов.

## Этап 3. Технический план и проверка Windows-интеграций

Предварительный стек: C# + WPF, локальное хранилище, Win32 для системных интеграций, Inno Setup. Окончательный выбор хранилища и версий зависимостей — после проверки окружения.

До основной разработки проверить маленьким техническим прототипом:

- Размытие, прозрачность, скругления и читаемость.
- Глобальные сочетания, перевод фокуса в быстрый ввод, возврат к предыдущему приложению.
- Трей, скрытие из панели задач, закрепление поверх окон.
- Поведение Win+D и выбранного режима рабочего стола.
- Масштабирование и восстановление позиции при отключении монитора.

Результат: проверенная архитектура и последовательный план реализации. Если настоящий desktop-режим потребует нестабильных механизмов Explorer, отдельно согласовать компромисс после прототипа.

## Этап 4. Рабочая основа

Реализовать модель задач, сохранение, добавление, редактирование, выполнение, восстановление, сроки и группировку. Затем секундомер и быстрый ввод.

Проверки: даты и переход суток, неверный ввод, сохранение и восстановление, отмена удаления, переключение секундомера, перезапуск приложения.

Результат: функциональная локальная версия без потери задач при штатной работе.

## Этап 5. Виджет и визуальная полировка

Соединить согласованный дизайн с рабочей основой. Завершить трей, горячие клавиши, закрепление, автозапуск, сохранение геометрии и выбранный desktop-режим.

Проверки: браузер → горячая клавиша → ввод → возврат; работа только клавиатурой; длинные списки; разные обои; масштаб Windows; сон и пробуждение; повторный запуск приложения; недоступная горячая клавиша.

Результат: кандидат на релиз, удобный для ежедневного использования.

## Этап 6. Установщик и проверка поставки

Собрать автономную Windows x64-версию и установщик Inno Setup. Установка для текущего пользователя по возможности без прав администратора. Проверить установку, запуск, обновление поверх старой версии и удаление. Пользовательские задачи сохранять при обновлении; удаление данных не делать неявно.

Результат: проверенный установщик и воспроизводимый сценарий сборки. Если проверка на чистой Windows недоступна, явно зафиксировать это ограничение.

## Этап 7. Публичный GitHub-релиз

Подготовить README с изображениями интерфейса, инструкциями установки и сборки, горячими клавишами, расположением данных и известными ограничениями. Предварительная лицензия — MIT.

Проверить состав публикации: исходники, необходимые ресурсы, скрипты сборки, Inno Setup, документация. Не публиковать личные задачи, локальные настройки и секреты. Готовый установщик приложить к GitHub Release.

Определить доступный GitHub-аккаунт и свободное имя репозитория при подготовке публикации. Публичная публикация запрошена пользователем.

Результат: открытый репозиторий и скачиваемый релиз. Подпись установщика зависит от наличия сертификата; статус подписи указывается в релизе.

## Цикл после 0.1.9

Решение пользователя 26 сентября. Требования и проверки — [SPEC, раздел 12](SPEC.md#12-следующий-цикл-после-019). Этапы идут по порядку; новые функции начинаются только после закрытия первой версии и надёжности.

### Этап A. Закрыть первую версию на текущей сборке

- V13: реальный сон с идущим таймером на 0.1.9.
- V10 и N03: масштаб 100, 125, 150 и 200 % на основном экране; геометрия, стекло и текст.
- V02: подключение и отключение внешнего монитора, перезапуск Explorer (только по отдельной договорённости).
- V12: чистая Windows без инструментов разработки — установить, создать задачу, обновить, удалить. Windows Sandbox на этой машине не запускается, поэтому второй ноутбук или виртуальная машина; там же разобрать ошибку установщика 267.
- Разбор `slow_request` в журнале рабочей копии после 1–2 недель работы.

Сон, масштаб, монитор и чистая Windows требуют действий пользователя: смена масштаба — системная настройка, сон и монитор — физические действия. Проверки готовятся заранее и запускаются вместе.

Результат: каждая проверка PASS или записанный дефект с воспроизведением.

### Этап B. 0.1.10 — надёжность

N06 запись вне потока окон, N07 контрольные точки раз в 15 секунд, N08 ротация журнала, N09 обновление при работающем Delo. Без новых функций. Результат: V14–V17 PASS, выпуск 0.1.10.

### Этап C. CI и подпись

N10 GitHub Actions на PR, затем заявка в SignPath Foundation (N11): CI, двухфакторная защита аккаунта, политика подписи. Одобрение зависит от SignPath; до него релизы остаются неподписанными.

### Этап D. 0.2.0 — функции

Начинается с набросков (решение 26 сентября, U08): для каждой функции показать, где она живёт, и что главный экран не изменился. Наброски: [design/sketches-0.2](design/sketches-0.2/index.html), 26 сентября. Реализация — после выбора пользователем варианта. Порядок: F03 забытый таймер → F04 статистика времени → T07 напоминание перед сроком → T08 даты в тексте → A05 поиск → N12 экспорт и импорт → F05 таймер с клавиатуры → N13 проверка обновлений.

### Открытые решения

Все решены 26 сентября по наброскам: забытый таймер — вариант A (в полосе задачи), даты в тексте — вариант B (подсказка над вводом), П9–П12 по предложенным значениям, «В архив» остаётся тёмно-оранжевым.

## За пределами первой версии

Облачная синхронизация, аккаунты, мобильное приложение, командная работа, AI-функции, проекты и теги, сложные повторения, календарные интеграции, Pomodoro, магазин тем, автоматическое обновление.

## Согласованные решения

1. Настоящий виджет рабочего стола, видимый после Win+D, с возможностью закрепить поверх окон.
2. Первая версия: русский, украинский и английский интерфейс.
3. Выполненные остаются зачёркнутыми до конца дня, затем архивируются. При закрытом приложении архивирование выполняется при следующем запуске.

Ответы на вопросы → согласование roadmap → визуальный макет и технический план → реализация → проверки → установщик → публичный релиз.

Текущая модель по сообщению пользователя: Astra Light. Выбор принят для формирования roadmap; для сложной реализации и отладки рекомендуется повысить рассуждение до High.
