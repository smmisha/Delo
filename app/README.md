# Delo — приложение в разработке

Delo — локальный планировщик для Windows 11 x64: постоянный виджет рабочего стола, быстрое добавление задач, таймер, архив, корзина и репутация. Интерфейс поддерживает русский, украинский и английский языки, системную, светлую и тёмную темы. Нативный Win32-host объединяет D3D11/WGC/DirectComposition для стекла с преломлением и прозрачный WebView2 для резкого интерфейса.

Проект ещё не является готовым публичным релизом. Основные сценарии работают и установщик собирается, но полный аудит `SPEC.md`, несколько мониторов/DPI, чистая Windows без SDK и публичная публикация пока не закрыты. Win+D и реальный сон на основном ноутбуке уже проверены в production host.

## Сборка

Нужны Windows 11, Visual Studio Build Tools с C++ workload, Windows SDK с C++/WinRT и PowerShell. Node.js нужен только для JS-тестов. `toolchain.ps1` автоматически находит последнюю подходящую установку MSVC и Windows SDK; при необходимости используйте `DELO_VC_ROOT`, `DELO_SDK_ROOT` и `DELO_SDK_VERSION`.

```powershell
./setup.ps1
./build.ps1
node --test tests/*.test.mjs
./test-store.ps1
./test-renderer.ps1
```

`setup.ps1` загружает WebView2 SDK 1.0.4191.47 и проверяет SHA-256. `build.ps1` статически связывает MSVC runtime и WebView2Loader, поэтому конечному пользователю не нужны Visual Studio Build Tools или Windows SDK. Для работы приложения нужен Microsoft Edge WebView2 Runtime.

## Установщик

Для локальной упаковки нужен Inno Setup 6.7 или новее и подписанный Microsoft автономный установщик WebView2 x64.

```powershell
./setup-distribution.ps1
./package.ps1 -Version 0.1.1
```

Если Inno Setup установлен в другом месте, передайте путь через `-Compiler`. Результат и его SHA-256 создаются в `dist/`. Установка выполняется для текущего пользователя в `%LOCALAPPDATA%\Programs\Delo`; права администратора для самого Delo не требуются. В комплект входит автономный установщик WebView2: он запускается только при отсутствии подходящего runtime.

Перед обновлением или удалением закройте Delo через значок в области уведомлений. Обновление заменяет файлы приложения. Удаление убирает приложение, ярлык и принадлежащую Delo запись автозапуска, но сохраняет пользовательские задачи и не удаляет общий WebView2 Runtime.

## Использование

- Введите задачу в нижнем поле и нажмите Enter. Shift+Enter добавляет новую строку. В быстром окне Escape отменяет ввод и очищает черновик; в основном окне Escape скрывает список.
- Глобальное сочетание списка по умолчанию — Ctrl+Alt+Space, быстрого окна — Ctrl+Alt+N. Конфликты показываются в интерфейсе, а прежние рабочие сочетания сохраняются.
- Автозапуск выключен по умолчанию и меняется в настройках.

Обычные данные находятся в `%LOCALAPPDATA%\Delo\tasks.json`, резервная копия — `tasks.json.bak`. Хранилище пишет атомарно, проверяет схему и блокирует сохранение поверх повреждённого файла. Явное восстановление из backup сохраняет копию повреждённого оригинала. Таймер использует общий монотонный отсчёт нативного процесса; checkpoint записывается каждые 5 секунд и после аварии восстанавливается в состоянии паузы.

Нативный renderer захватывает фон монитора с исключением собственного окна, размывает его двумя Gaussian-проходами и выполняет отдельный проход преломления, tint и rim. Реальный sleep/resume production app проверен с работающим таймером, восстановлением renderer и последующим relaunch. При сбое захвата приложение сохраняет читаемый fallback; искусственный сбой GPU и физическая смена мониторов ещё требуют проверки.

## Изолированный harness

`bin/Delo.exe --harness=<имя>` использует `bin/test-output/sessions/<имя>` и включает локальный диагностический CDP-порт 9223. Обычный запуск не включает harness. Всегда задавайте отдельное имя сессии: безымянный старый каталог может содержать реальные личные задачи. Каталоги `bin`, `vendor`, `test-output`, `dist` и снимки рабочего стола не публикуются.

Текущее локальное доказательство включает 28 JS-тестов, 20 native store/hotkey assertions, 9 реальных GPU-тестов и живые проверки диалогов, quick-window, ввода/редактора, контекстного меню, трёх языков, undo/корзины, восстановления backup и конфликтов hotkey. Production host прошёл Win+D; на неподвижном рабочем столе за 10 секунд было 0 новых presents, renderer остался healthy, а процесс использовал около 0,13% одного ядра и 54,69 МиБ рабочей памяти. Также выполнен цикл установки 0.1.0, обновления до 0.1.1, запуска и удаления с сохранением изолированных данных. Это не заменяет полный verification audit и тест на чистой Windows без SDK.
