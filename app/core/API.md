# Domain integration

`model.mjs` is a dependency-free ES module. All domain timestamps are epoch milliseconds except `timerAnchor`, which is a session-local monotonic millisecond timestamp, and duration fields. Pass `{now: Date.now(), monotonic: performance.now(), timeZone: Intl.DateTimeFormat().resolvedOptions().timeZone}` explicitly to every command. Never reuse a timer anchor across processes.

`createState()` creates schemaVersion 1. `applyCommand(state, command, clocks)` clones state and returns a candidate new state; it never mutates its argument, including when validation throws. The caller serializes all commands and persists the whole candidate before committing it to the view. Failed persistence retains the old state and input. Host uses revision/CAS to prevent simultaneous windows overwriting each other. Run `tick` on load and periodically to process deadlines, archival, and retention. Compare candidate to prior state to skip a write for an unchanged tick.

Commands: `create {id,title,due?}`, `edit {id,title}`, `deadline {id,due}`, `start`, `pause`, `stop`, `work`, `complete`, `uncomplete`, `delete`, `restore` (all with id); `undo {id?}` defaults to latest deletion; `advanceUndo {delta,paused}` advances all pending windows using a single monotonic UI source; `finalizeDeletes`, `settings {patch}`, `tick`, `suspend`, `checkpoint`. `due` is null or `{date:'YYYY-MM-DD',time:'HH:mm'|'',timeZone:'Europe/Kyiv'}`. `makeDeadline` validates and returns the canonical object with fixed `at`. Spring-forward gaps are rejected; repeated fall-back local times select the earliest instant.

Before sleep and ordinary exit send `suspend`, then `finalizeDeletes` on exit, and save. Every five seconds while running send `checkpoint`; maximum crash loss is the interval since successful checkpoint. On load call `validateState` (returns `{valid,error?}`), then `recoverState` (throws on corruption, pauses saved timers without adding downtime, and finalizes pending deletions). Recovery never substitutes a blank database. Keep corrupt source and backup handling in host storage.

Task fields: `id,title,createdAt,lifecycle,workState,elapsedMs,timerAnchor,due,completedAt,completedDayEnd,award,penalties,archiveAnchor,deletedAt,undoRemaining`. Lifecycle is active/archive/pending/trash. Work is idle/running/paused/working; completion is independent (`completedAt !== null`). `elapsed(task,monotonic)` computes display time, `formatElapsed(ms)` supports hours beyond 24. `groups(state,{now,timeZone})` returns nonempty `{key,tasks}` groups in late/today/upcoming/any/done order.

State contains tasks, settings, reputation and a persistent events ledger. Event shape is `{id,taskId,kind,at,delta}`; kinds first/week/complete/uncomplete. `deleteEvent` identifies one exact ledger entry by all five fields, removes it, reverses its delta in reputation and compacts the remaining IDs. Paid penalty flags stay set when their visible history entry is removed, so the same overdue penalty is never charged again. Play sounds only for newly persisted live events, never for initial catch-up or recovery. Task IDs must be globally unique strings supplied by host/UI. Text trims outer whitespace, retains internal newlines, and has a 20,000 UTF-16-code-unit bound.

Defaults P1-P8 are implementation choices, not retrospectively user-approved specification changes. Settings keys: language ru/uk/en, theme system/light/dark, autoArchive all/dated/undated/off, archiveDays 1/7/30/90, completionSound, overdueSound, autostart, pinned, listShortcut, quickShortcut. Native host owns shortcut parsing/conflict validation. Creation time remains immutable; archiveAnchor resets on restore. Penalties are lifetime one-time flags and reputation may be negative. Equal-time penalties precede archive; archive suppresses later penalties. Trash retention starts at initial delete, irrespective of undo-window pause.
