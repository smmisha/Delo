# Стекло: рабочий стол и поверх окон

10 сентября 2026. **Рабочая оконная модель проверена: 49 проверок прошли, ошибок нет.** В журнале ещё четыре диагностические записи о геометрии/источнике; они не включены в число проверок. Два полных цикла desktop → topmost выполнены с живым monitor capture и HLSL-материалом, в светлой и тёмной контрольных палитрах.

## Выбранная модель прототипа

Окно материала остаётся верхнеуровневым `WS_POPUP | WS_EX_TOOLWINDOW | WS_EX_NOREDIRECTIONBITMAP`. В режиме рабочего стола его **владельцем** назначается обнаруженный desktop-host Explorer через GWLP_HWNDPARENT; topmost снимается, окно опускается вниз. Оно остаётся выше владельца и ниже обычных приложений. В режиме «поверх окон» владелец снимается и применяется HWND_TOPMOST. Реальный HWND Explorer каждый раз обнаруживается по SHELLDLL_DefView; числовой handle не зашит.

Это ownership, не WS_CHILD/SetParent. Собственный HWND сохраняет применимость SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE). После каждого перехода исключение и пиксели фона проверяются заново. Стеклянное окно не пересоздаётся, D3D-устройство и swap chain сохраняются.

Прямой вариант WS_CHILD также повторно проверен на окончательной сборке: настройка исключения возвращает **ошибку 87**, поэтому его цикл останавливается. [Отрицательный контроль](evidence/glass-modes-2026-09-10/child.jsonl). Он не выбран для реализации Delo.

## Надёжность контрольной сцены

Для desktop и topmost создаются разные собственные источники сетки. Они не переносятся SetParent между процессами, что устраняет влияние такого переноса на DPI-состояние. Источник рабочего стола — layered child с непрозрачной альфой, созданный сразу в desktop-host. Для него добавлен manifest совместимости Windows 10, необходимый для поддержки layered child. Сам виджет layered child не использует.

Ранние чёрные кадры были недостоверным испытанием оптики: обычный GDI-источник в desktop-host не давал требуемую сетку. В итоговом пробнике проверяются оба ожидаемых цвета и их количество **до** включения линзы; чёрный источник больше не может пройти проверку отсутствия самозахвата. Ранний независимый вариант с перехватом собственных оконных сообщений удалён; в выбранной модели нет подавления Win+D, хуков Explorer или подмены системных сообщений.

В monitor-пробнике добавлен только guard entry point для повторного использования; его самостоятельная сборка после изменения прошла. Ранние неподтверждённые прогоны не включены в успешный журнал. После финальных запусков процессов пробника не осталось; собственные окна закрыты, Win+D переключён обратно, положение указателя восстановлено.

## Воспроизведение

В `prototypes/gpu-glass` выполнить `build-modes.ps1`, затем `run-modes.ps1`. На время прогона не переключать окна и не удерживать модификаторы: тест использует реальный Win+D, мышь и один символ внутри собственного окна. По умолчанию запускается рабочий owner-вариант. `Delo.WindowModesProbe.exe --child` — отдельный отрицательный диагностический контроль, ожидаемо возвращающий код 1.

## Что ещё требуется до утверждения стека

Проверены Windows 11 25H2, основной монитор 1920×1200, масштаб 125%, AMD Radeon 610M. Не проверены Explorer restart, сон/пробуждение, несколько мониторов, смена DPI и размеров, потеря capture/device. Нельзя обещать переносимость обнаруженного desktop-host на все сборки Windows. Уничтожение владельца может повлиять на принадлежащее ему окно — восстановление HWND и renderer необходимо проверить отдельно.

Проверка ввода ограничена диагностическим окном: интерфейс задач, IME, глобальный быстрый ввод и возврат фокуса с новым renderer ещё не реализованы. Частота кадров, задержка, CPU/GPU/RAM и idle-режим не измерялись. Это архитектурный прототип; SPEC и утверждённый дизайн не изменены. Delo пока не Git-репозиторий, поэтому git diff недоступен.

## Первичные источники

- [SetWindowLongPtrW](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowlongptrw): GWLP_HWNDPARENT задаёт владельца top-level HWND; для родителя дочернего окна используется другой механизм.
- [Window Features](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features): owned windows и порядок окон.
- [Using Windows](https://learn.microsoft.com/en-us/windows/win32/winmsg/using-windows): layered child и manifest совместимости.
- [SetWindowDisplayAffinity](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity): исключение собственного top-level окна из захвата.

Поведение Win+D подтверждено экспериментально; оно не выдано за универсальную гарантию из документации ownership.
