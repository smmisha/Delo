## Формат поставки

Отдельный `app/package-msix.ps1` собирает существующее Win32-приложение x64 и создаёт unsigned MSIX для подписи Microsoft Store. `app/msix/StoreIdentity.json` содержит фактические значения кабинета. Упаковщик проверяет версию EXE и хеши голосовых зависимостей, использует явный список файлов, включает лицензии и исключает объектные файлы, тесты и пользовательские профили. Пакет собирается Windows SDK MakeAppx с проверкой manifest.

Store-поставка определяется по package identity во время запуска. Автозапуск использует manifest StartupTask (`DeloStartup`, выключен по умолчанию), учитывает состояние и запреты Windows; обычная EXE-поставка сохраняет HKCU Run. Store-поставка не обращается к GitHub Releases и показывает ссылку на Microsoft Store. Политика из `PRIVACY.md` генерируется в локальную HTML-страницу и доступна через настройки.

Store-профиль использует `ApplicationData.Current.LocalFolder`; он отделён от обычного `%LOCALAPPDATA%\Delo`. Для переноса служат существующие экспорт и импорт. Обновление должно сохранять профиль; удаление или сброс MSIX могут удалить данные. Эти операции с зарегистрированным пакетом ещё не проверены.

Окончательные EXE и MSIX собраны, MakeAppx PASS. SHA-256 окончательного пакета: `E7691FBE4DF7A657FED24108EE5939B61CED8409D512B9BF4144E0378FA00C28`. Выполнены 85 JS-тестов (повторно после последнего изменения UI), 39 native storage/hotkey проверок и 9 GPU проверок, все PASS. `git diff --check` PASS. Серверная проверка Microsoft также приняла окончательную пересобранную сборку.

Через CUA проверен исходный WebView-интерфейс в локальном браузерном стенде с имитацией native bridge: RU/UK/EN, светлая и тёмная тема, Store-строка обновлений, вызовы кнопок Store и privacy, запрет переключателя автозапуска при блокировке Windows. Следующая загрузка должна иметь версию выше, поэтому очередной выпуск — **0.3.3**, и для Store, и для `.exe` на GitHub. Версии 0.3.2 на GitHub нет: это был пакет только для Store.

**Жёлтая рамка в установке из Store.** Причина: для приложения с package identity Windows убирает рамку захвата только после двух шагов — объявить в манифесте возможность `graphicsCaptureWithoutBorder` (`uap11:Capability`, общая возможность, одобрение Microsoft не нужно) и один раз получить согласие пользователя через `GraphicsCaptureAccess.RequestAccessAsync(Borderless)`. Ни того ни другого в 0.3.2 не было, а `IsBorderRequired(false)` без согласия молча игнорируется. В неупакованном `.exe` рамка снимается без согласия, поэтому там её нет. Windows 10 22H2 (сборка 19045) этого API не имеет: рамка там остаётся всегда (см. WINDOWS10-COMPATIBILITY.md).

**Правка 0.3.3.** В манифест добавлена `uap11:Capability graphicsCaptureWithoutBorder` (`uap11` внесён в `IgnorableNamespaces`, чтобы Windows 10 пропускал элемент). В `StoreDistribution.h` запрос согласия выполняется один раз при запуске упакованной версии на отдельном потоке, чтобы окно согласия не блокировало хост; результат хранится в `borderlessAccess`. Если ответ пришёл после создания захвата, `GlassRenderer.cpp` один раз пересоздаёт сессию захвата, уже с согласием. Windows запоминает выбор: при следующих запусках запрос возвращается сразу. **Не проверено:** сам пакет с этой правкой на Windows 11 и на Windows 10 (манифест принят `makeappx`, код собран); подтвердить рамку можно только установкой Store-версии 0.3.3, где один раз появится окно согласия.

**Происшествие с локальными файлами.** Пробная локальная упаковка `package-msix.ps1 -Version 0.3.2`, запущенная при проверке, перезаписала `app/dist/Delo-0.3.2-store-x64.msix` и `.sha256`, а также `app/test-output/msix-0.3.2/`. Опубликованный в Store пакет 0.3.2 (SHA-256 `D4D4D23F…`) лежит у Microsoft и не затронут, исходники — коммит `90882ff`; локальная копия с тем же именем теперь переименована в `…NOT-THE-PUBLISHED-ONE` и не совпадает с опубликованной. Байтово тот же файл повторить нельзя: сборка не детерминирована.

**Отправка 0.3.3.** 2 октября вечером пользователь сам загрузил `Delo-0.3.3-store-x64.msix` (SHA-256 `7B0D86A5…937E`) в продукт 9MSPF2LJL0V2 и отправил на сертификацию; ждёт результата. Что подтвердить после публикации: обновление из Store, окно согласия на захват без рамки при первом запуске, исчезновение жёлтой рамки на Windows 11 (на Windows 10 рамка остаётся). Если рамка осталась, смотреть `native.jsonl` установленной версии и результат `IsBorderRequired` в диагностике рендера.

**Результат 0.3.3 (3 октября).** Сертификация пройдена. Пользователь проверил установку из Store на Windows 11: при первом запуске Windows показывает окно согласия на захват экрана, после «Разрешить» жёлтая рамка пропадает и виджет работает нормально. Правка рамки подтверждена вручную. Публичные данные Store (storeedge) показывают обновление 2 октября 18:40 UTC, но не номер версии пакета. Замечание пользователя: окно согласия может насторожить обычного пользователя (слежка за экраном); убрать его нельзя, это системный запрос Windows, но можно заранее объяснить в самом виджете и в карточке Store.
