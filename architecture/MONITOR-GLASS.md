# Реальный фон рабочего стола — успешная проверка

10 сентября 2026. **25/25 проверок, код завершения 0.** Рабочий D3D11/HLSL-шейдер получил фон монитора через Windows Graphics Capture. Обои и значки действительно преломляются у кромки; собственный виджет исключён из захвата.

## Реализация

[MonitorProbe.cpp](../prototypes/gpu-glass/MonitorProbe.cpp) использует проверенный GPU-код из Probe.cpp и неизменённый Glass.hlsl. В Probe.cpp добавлена только условная компиляция entry point для повторного использования; самостоятельная сборка прежнего пробника после этого прошла.

CreateForMonitor захватывает основной монитор 1920×1200. До CPU readback на GPU вырезается только участок 400×300 под линзой, с учётом начала координат монитора. SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE) применяется к собственному верхнеуровневому HWND. Свойство прочитано обратно и проверено.

Маленькое собственное окно 8×8 вне исследуемой области вызывает новый кадр даже на неподвижном рабочем столе. Это средство диагностики, не будущий механизм обновления приложения. Пробник не активирует чужие окна и не восстанавливает свёрнутые приложения после завершения.

Сборка MSVC 14.50.35717 / SDK 10.0.26100.0 прошла без предупреждений. GPU — AMD Radeon 610M. [Журнал](evidence/monitor-glass-2026-09-10/checks.jsonl), [хеши и параметры](evidence/monitor-glass-2026-09-10/build.json).

## Граница успеха и следующая проверка

Это успех **верхнеуровневого окна** с реальным фоном. SetWindowDisplayAffinity документирован для top-level HWND своего процесса; совместимость исключения с привязкой к Explorer пока не проверена. Нельзя считать прежний Win+D-тест простого окна подтверждением работы нового renderer.

Следующий этап: проверить desktop-привязку, topmost-переходы, Win+D и ввод вместе с этим материалом. При изменении оконной модели снова провести контроль самозахвата; если исключение перестаёт работать, не запускать цикл обратной связи и не маскировать проблему размытием.

Исключение также означает, что виджет может отсутствовать в обычной записи экрана/скриншотах — это свойство выбранного механизма. Нужен продуманный способ экспорта самого виджета. FPS, задержка, нагрузка CPU/GPU/RAM, работа в покое, несколько мониторов, HDR, DPI-переходы, сон и восстановление устройства здесь не оценивались. Две палитры тестовой сетки не равны готовым светлой/тёмной темам приложения.

## Воспроизведение и первичные источники

В папке `prototypes/gpu-glass` выполнить `build-monitor.ps1`, затем `run-monitor.ps1`. На время короткого прогона оставить рабочий стол без переключений окон. Скрипт сохраняет только исследуемый участок, показывает собственные контрольные окна и закрывает их. Непройденная проверка даёт ненулевой код; при провале исключения цикл линзы не запускается.

- [Microsoft CreateForMonitor](https://learn.microsoft.com/en-us/windows/win32/api/windows.graphics.capture.interop/nf-windows-graphics-capture-interop-igraphicscaptureiteminterop-createformonitor).
- [Microsoft SetWindowDisplayAffinity](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowdisplayaffinity): top-level HWND своего процесса, значение WDA_EXCLUDEFROMCAPTURE.

Обновление: desktop/topmost, Win+D и диагностический ввод с этим материалом теперь проверены в owner-модели — [GLASS-WINDOW-MODES.md](GLASS-WINDOW-MODES.md). Прямое превращение окна материала в WS_CHILD не поддерживает необходимое исключение.
