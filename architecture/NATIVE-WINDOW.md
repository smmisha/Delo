# Delo — минимальное нативное окно

10 сентября 2026. Исследование Win32/C++/WinRT без WinForms. **Окно и обработка внешнего фона стандартным эффектом подтверждены, включая desktop-режим после Win+D. Последующий тест преломления не прошёл — см. REFRACTION.md.**

## Проведённый эксперимент

Три конфигурации получают отдельные свежие HWND: верхнеуровневое окно, дочернее окно Explorer с WS_EX_NOREDIRECTIONBITMAP и такое же дочернее окно с дополнительным WS_EX_LAYERED. Родитель задаётся при создании, до создания Composition-target. Это не проверка перепривязки одного действующего HWND.

Под поверхностью находится собственное окно с заливкой, меняющейся с голубой на красную. Проверяются красная Composition-поверхность, прозрачный контроль, HostBackdropBrush и обычный BackdropBrush через стандартный opacity-effect. Для desktop-конфигураций измерения выполняются после Win+D, затем сочетание повторяется для возврата окон.

| Проверка | Верхнеуровневое окно | Desktop без layered | Desktop с layered |
| --- | --- | --- | --- |
| Создание / правильный родитель | Да | Да | Да |
| Красный Composition-контроль | Да | Да, после Win+D | Да, после Win+D |
| Прозрачный контроль показывает смену фона | Да | Да | Да |
| BackdropBrush реагирует на смену фона | Да | Да | Да |
| Saturation=0 обесцвечивает внешний фон | Да | Да, после Win+D | Да, после Win+D |
| HostBackdropBrush реагирует на фон | Нет, чёрный | Нет, чёрный | Нет, чёрный |
| DWM host-backdrop / расширение рамки | HRESULT=0 | Ошибки | Ошибки |

Во всех трёх конфигурациях обычный BackdropBrush дал COLORREF **15116820 → 1981680**, совпадающий с цветами внешней заливки. HostBackdropBrush дал **0 → 0**. Для дочерних HWND DWM вернул **0x80070006** и **0x80070057**. Эти неудачи сохранены в отчёте, а не исключены из подсчёта.

Первый прогон: **17 успешных проверок из 22**, код выхода **1**. [Исходный журнал](evidence/native-window-2026-09-10.jsonl), локальное время завершения 11:09.

Повторный прогон с Saturation: **20 успешных проверок из 25**, код выхода **1** из-за тех же пяти ошибок HostBackdrop / DWM. Все три новые проверки обработки внешнего фона прошли. [Журнал повторного прогона](evidence/native-window-saturation-2026-09-10.jsonl), [хеши исходников и запущенного EXE](evidence/native-window-saturation-2026-09-10-build.json). Тестовый процесс завершился; оставшихся процессов пробника не обнаружено. Снимки ограничены прямоугольниками тестовых поверхностей и остаются в исключённом `bin`; визуальная оценка этих BMP не проводилась.

## Что этот результат доказывает

Чистое нативное окно с Composition-target можно создать непосредственно в desktop-host на проверенной машине и отрисовать после Win+D. Ошибка SetParent прежнего WinForms-прототипа не воспроизведена на этом пути создания. Причина ошибки в WinForms отдельно не установлена.

Проходящий opacity-effect с коэффициентом 1 визуально неотличим от простой прозрачности. Дополнительный Saturation-контроль подтвердил обработку обычным BackdropBrush внешнего фона через стандартный D2D-эффект. Это доказательство доступности источника для проверенного эффекта, но не работоспособности произвольного custom shader или библиотеки преломления.

## Результат дополнительной проверки

Стандартный D2D Saturation-effect с насыщенностью 0 превратил оба цветных внешних фона в разные оттенки серого. Проверка одновременно потребовала нейтральных каналов RGB, реакции на смену фона и отличия от исходных цветов. Во всех трёх конфигурациях получены COLORREF **9342606 → 6316128**, то есть RGB **(142,142,142) → (96,96,96)**. Прозрачное окно само по себе не могло бы так изменить цветную заливку за ним.

Первоначальная блокировка запуска из-за кредитов workspace устранена. Повторный запуск выполнен после сообщения пользователя о пополнении; новый журнал сохранён отдельно от первого.
