# П16: короткий запуск таймера после untimed-паузы, 27 октября 2026

## Причина и исправление

Старый предикат допускал целую секунду после untimed-маркера. Если версия без П16 сохраняла неизвестный маркер и успевала запустить и поставить таймер на паузу за это время, F05 выбирал work вместо start.

Новое touchedAt строго инвалидирует маркер. Для конца интервала сохранён только допуск 0,5 мс: record() округляет wall-clock начало через Math.round, поэтому конец корректного интервала может оказаться немного позже того же миллисекундного now. Отдельная регрессия защищает такую законную untimed-паузу.

В run-work-pause.ps1 запуск harness получает WindowStyle Hidden; сценарий показывает нужные окна штатными командами host.

## Проверка ошибки запуска harness

Launch завершает только созданный им процесс при ошибке готовности. До исправления принудительный таймаут оставлял настоящий Delo.exe работающим; после исправления тот же probe подтверждает завершение процесса. Отдельный обычный запуск возвращает работающий процесс и завершает сохранённый выход через host. Порт 9223 освобождается после завершения WebView2. Локальные timeout-before.json, timeout-after.json, normal-after2.json и probe.ps1 сохранены в app/test-output/pr15-launch-20261027/.

Проверены и замечания вне diff: settle теперь отклоняет фазу, если widget остаётся busy после таймаута. Замечание о touchedAt при последовательных F05 для legacy working-задач не подтвердилось: ветка pause уже записывает touchedAt=now. Добавлен API-тест с двумя working-задачами, паузами в разное время и JSON/recoverState; он проходит без изменения модели.

## Автоматическая пауза legacy-задачи

Подтвердился другой сценарий: working с touchedAt=10, paused-таймер с touchedAt=30; старт третьей задачи в 40 автоматически приостанавливает working, затем stop третьей задачи. Старый hold оставляет touchedAt=10, и F05 запускает прежний paused-таймер. Теперь hold записывает touchedAt=now при паузе working. Новая API-регрессия сначала падает (start paused вместо work working), после фикса весь набор этой ветки — 99/99 PASS.

Живой глобальный Ctrl+Alt+Shift+P в фоне другого процесса воспроизводит старое поведение и подтверждает исправление: old выбирает paused/running, fixed — working/working. Запуск третьего таймера и stop выполнены настоящими UI-командами. Доказательства: Delo-integration-check/app/test-output/automatic-pause-20261027/old.json и fixed-retry.json.
