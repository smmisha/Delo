## Причина и исправление

Собственный `evaluate(expression)` передавал только строку в `Runtime.evaluate`. Функция из вызова `evaluate(callback, argument)` исчезала при JSON-сериализации запроса. Настоящий CDP воспроизводил ошибку `-32602` с отсутствующим обязательным `params.expression`.

Для callback применяется `Runtime.callFunctionOn`; значения передаются через массив CDP arguments. Старые выражения-строки продолжают работать. Динамические аргументы аудитов переведены на этот путь вместо ручного экранирования строк.

В CI добавлен `audit-harness.test.mjs`: дочерний Node inspector обрабатывает настоящий WebSocket/CDP, подменяется только обнаружение страницы. Проверяются строки, аргументы-файлы, два селектора, JSON со спецсимволами, текст с JS-подобным содержимым, async-результаты и исключения.

В live-раннере также исправлены обнаружение страниц через явный разбор JSON и запись window.json без BOM. При диагностике `@(Invoke-RestMethod ...)` возвращал один объект `System.Object[]`, содержащий обе страницы. Исправленный путь различает about:blank, main и quick. Запись профиля проверена настоящим Windows PowerShell 5.1.26100.9711: BOM отсутствует, тестовые сочетания сохранены.

### Повтор дополнительных 23 проверок

`-Extra` запускает только voice fixtures (4), material-groups (11), затем scroll-fade (8) в одном новом harness. Голосовой аудит получает `--fixtures-only` и не открывает микрофон. Материальный аудит сам создаёт 20 синтетических задач; scroll-fade использует их в том же процессе.

Нужен отдельный standalone runtime с Whisper, собранный без `-SkipVoice`, и входной каталог с тремя контрольными файлами. Подготовьте PCM WAV, mono, 16 kHz, 16 bit, с отчётливо произнесёнными фразами:

| Файл | Пример фразы | Обязательные слова в распознанном тексте |
| --- | --- | --- |
| ru.wav | Купить молоко и записаться к врачу завтра. | молоко, затем врачу |
| uk.wav | Підтримати ініціативу та взяти участь у співі. | ініціативу, затем співі |
| en.wav | Buy milk and call the doctor tomorrow. | milk, затем doctor |

Файлы можно получить записью контрольной фразы или синтезом соответствующим языковым голосом. Например, в Windows PowerShell при наличии нужных голосов:

```powershell
$fixtures = Join-Path (Get-Location) ("app/test-output/voice-fixtures-" + [guid]::NewGuid().ToString("N"))
New-Item -ItemType Directory -Path $fixtures -Force | Out-Null
Add-Type -AssemblyName System.Speech
$texts = @{ru="Купить молоко и записаться к врачу завтра.";uk="Підтримати ініціативу та взяти участь у співі.";en="Buy milk and call the doctor tomorrow."}
foreach ($language in "ru","uk","en") {
    $speech = [System.Speech.Synthesis.SpeechSynthesizer]::new()
    try {
        $voice = $speech.GetInstalledVoices() | Where-Object { $_.Enabled -and $_.VoiceInfo.Culture.TwoLetterISOLanguageName -eq $language } | Select-Object -First 1
        if (-not $voice) { throw "Нет голоса ${language}: подготовьте соответствующий WAV отдельно. Не подменяйте язык другим голосом." }
        $speech.SelectVoice($voice.VoiceInfo.Name)
        $format = [System.Speech.AudioFormat.SpeechAudioFormatInfo]::new(16000,[System.Speech.AudioFormat.AudioBitsPerSample]::Sixteen,[System.Speech.AudioFormat.AudioChannel]::Mono)
        $speech.SetOutputToWaveFile((Join-Path $fixtures "$language.wav"),$format)
        $speech.Speak($texts[$language])
    } finally { $speech.Dispose() }
}
```

Не перезаписывайте сохранённые эталонные WAV при генерации новых: используйте новый входной каталог. `setup-voice.ps1` устанавливает Whisper, но не синтезирует WAV и не устанавливает языковые голоса. Если украинского голоса нет, заранее подготовьте uk.wav отдельной записью или синтезатором с украинским голосом; без всех трёх файлов runner завершится до запуска Delo. При повторном запуске с другими или пересозданными WAV-файлами используйте свежий runtime-каталог или предварительно очистите скопированные фикстуры (`Remove-Item -Recurse -Force ./app/build-audit/test-output/voice-fixtures`): runner отклоняет фикстуры, если их SHA-256 отличается от уже скопированных в runtime.

```powershell
# $fixtures — каталог уже подготовленных ru.wav, uk.wav и en.wav.
$session = "pr-extra-" + [guid]::NewGuid().ToString("N")
./app/tests/run-ui-audit.ps1 -RuntimeDirectory ./app/build-audit -SessionName $session -Extra -VoiceFixtureDirectory $fixtures -OutputDirectory (Join-Path ./app/test-output $session)
```

## Очистка стенда при ошибках — 28 октября

При ошибке сохранённого выхода runner завершает только запущенный им процесс и ждёт его остановки, затем сообщает об ошибке. В отдельном harness проверены обе ветки: ненулевой код команды выхода и отсутствие выхода в течение 10 секунд. В обоих случаях собственный PID завершился; освобождение TCP-порта заняло ещё около половины секунды.

Голосовой аудит сбрасывает `window.voiceFixture` в main и quick также при ошибке. Очистка ограничена двумя секундами; после неё обе CDP-сессии закрываются до записи отчёта. Закрытие CDP отклоняет незавершённые запросы и очищает их таймеры. Ошибка сериализации запроса также удаляет его таймер. Поэтому предел очистки больше не оставляет Node ждать стандартный тайм-аут CDP в 45 секунд.

`audit-harness-close.test.mjs` проверяет локальное закрытие, обрыв соединения и ошибку сериализации в отдельных Node-процессах с настоящим Inspector. До исправления падали все три сценария; после него вместе с существующими CDP-проверками проходят 11/11. Отдельный контроль с потерянным ответом очистки завершился за 2378 мс без активных таймеров, тогда как прежний процесс оставался жив через 7500 мс и был остановлен проверяющим процессом. JS-тесты первого повтора: 106/106 PASS. Локальные доказательства: `app/test-output/codex-verify-antigravity-20261028/` и `app/test-output/codex-fix-followups-20261028/`.

Штатный повтор `-Extra` после исправления очистки: voice 4/4, material-groups 11/11, scroll-fade 8/8, код выхода runner 0. Отдельно группы прошли ещё три последовательных диагностических повтора. Зафиксированные ранее непостоянные падения сворачивания и колёсика не воспроизвелись; их причина не доказана. Продуктовый UI и assertions этих аудитов не менялись, поэтому этот повтор не является доказательством устранения прежней нестабильности.

Отдельная регрессия подтверждает ровно один `Runtime.releaseObject` после ошибки сериализации аргумента и дальнейшую работоспособность соединения.
