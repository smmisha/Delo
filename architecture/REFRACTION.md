# Delo — проверка преломления внешнего фона

10 сентября 2026. **Проверка не прошла.** Работоспособность обычного BackdropBrush для Saturation не означает, что его можно пространственно деформировать. Полноценное нативное Liquid Glass пока не подтверждено.

## Метод

Собственный Win32/C++/WinRT-пробник использует ранее проверенный host и отдельное собственное окно с контрастной сеткой. Пользовательские окна и обои не служат тестовыми данными. Оптика построена через документированный D2D affine-transform и 24 непересекающиеся округлые полосы шириной 1 px. Масштаб меняется от 1.12 у края до 1 в центре. Это приближение линзы для проверки источника, не финальный дизайн или физический шейдер.

Проверены два пути:

1. Прямое подключение BackdropBrush к affine-effect.
2. Промежуточная CompositionVisualSurface, у которой SourceVisual отображает BackdropBrush через opacity-effect; преобразование применяется к SurfaceBrush этой поверхности.

Контроль — сетка, нарисованная внутри Composition. Она проверяет тот же дескриптор эффекта, геометрию, SurfaceBrush и алгоритм сравнения независимо от внешнего источника. Скриншоты получены только из прямоугольника тестовой поверхности. Сравнение проводится до tint и бликов, чтобы изменение цвета не было принято за пространственное смещение.

## Фактические результаты

| Сценарий | Результат |
| --- | --- |
| Affine-effect + цветовая кисть | Источник подключается |
| Affine-effect + BackdropBrush | SetSourceParameter отклонён: E_INVALIDARG, 0x80070057 |
| Линза на внутренней контрольной сетке | 1173 изменённых пикселя у кромки; изгиб виден на снимке |
| Внешняя сетка через VisualSurface, topmost, светлая тема | 0 изменённых пикселей у кромки |
| Внешняя сетка через VisualSurface, topmost, тёмная тема | 0 изменённых пикселей у кромки |
| Внешняя сетка через VisualSurface, desktop после Win+D, светлая тема | 0 изменённых пикселей у кромки |
| Внешняя сетка через VisualSurface, desktop после Win+D, тёмная тема | 0 изменённых пикселей у кромки |
| Смена положения внешней сетки | Видима во всех четырёх сценариях, но не доказывает её захват VisualSurface: фон может быть виден через прозрачные участки |
| Центр изображения | Не изменился; сам по себе этот контроль не доказывает преломление |
| Ввод и переключение действующего окна с этим материалом | Не выполнялись: условие успешной оптики не выполнено |

Проверка обеих тем и внутренняя контрольная сетка просмотрены на фактических снимках. На внешней сетке линии прямые; на внутренней изгибаются. На внутренней контрольной линзе также видны артефакты у углов: этот способ ещё не соответствует финальному визуальному качеству Delo даже для внутреннего источника.

Финальный процесс завершился кодом **1**, оставшихся процессов пробника не обнаружено. [Журнал](evidence/refraction-2026-09-10.jsonl), [хеши исходников и EXE](evidence/refraction-2026-09-10-build.json). В журнале `interaction_skipped_optics_failed` обозначает невыполненное условие запуска, а не провал реально проведённого теста ввода. Предыдущие успешные проверки обычного окна и Saturation сохраняют своё отдельное значение.

## Что изменено

- [RefractionProbe.cpp](../prototypes/windows-layer/RefractionProbe.cpp): оптический контроль, обе темы, desktop / topmost, сравнение пикселей. Ветка последующих проверок ввода и перепривязки подготовлена, но не запускалась и не считается проверенной.
- [RefractionEffect.h](../prototypes/windows-layer/RefractionEffect.h): оригинальные дескрипторы стандартного affine-effect и публичного geometry interop. Код сторонних репозиториев не переносился.
- [build-refraction.ps1](../prototypes/windows-layer/build-refraction.ps1): сборка существующими локальными MSVC / SDK. Установка зависимостей не потребовалась.
- В NativeWindowProbe.cpp добавлено условное исключение entry point для повторного использования диагностических функций. Его самостоятельная сборка после изменения также прошла; прежний тест заново не запускался.

Принятый интерфейс `design/index.html` не изменялся. EXE, BMP и PNG находятся в исключённом `bin`, публикация не выполнялась. В Delo по-прежнему нет Git-репозитория; проверка через git diff недоступна.

## Вывод и следующий исследовательский шаг

Путь «стандартный affine-effect непосредственно на Windows.UI.Composition BackdropBrush» на проверенной машине не работает. VisualSurface в проверенной конфигурации не дала преломление внешнего фона. Нельзя считать это доказательством невозможности эффекта через другие API, другой compositor или другую библиотеку.

Следующий эксперимент требует другого механизма оптики: проверить отдельный WinUI 3 / HLSL-кандидат с реальным внешним источником и явно зафиксировать его зависимости от внутренних API. Источник и смещение снова проверять раздельно. До успешного результата не переходить к производственной реализации или утверждению стека. Обновление: кандидат LiquidGlassWinUI теперь установлен, собран и проверен отдельно; [результат также отрицательный](WINUI-GLASS.md).

## Первичные источники

- [Microsoft Win2D DisplacementMapEffect](https://microsoft.github.io/Win2D/WinUI2/html/T_Microsoft_Graphics_Canvas_Effects_DisplacementMapEffect.htm): помечен NoComposition; не поддерживается Windows.UI.Composition.
- [Microsoft Transform2DEffect](https://microsoft.github.io/Win2D/WinUI2/html/T_Microsoft_Graphics_Canvas_Effects_Transform2DEffect.htm): стандартное аффинное преобразование.
- [Microsoft Win2D, описание свойств Transform2DEffect](https://github.com/microsoft/Win2D/blob/master/winrt/lib/effects/generated/Transform2DEffect.cpp): проверены типы свойств и матрицы; код в проект не копировался.
- [Microsoft Composition brushes](https://learn.microsoft.com/en-us/windows/apps/develop/composition/composition-brushes): типы источников и ограничения их сочетаний. Поддержка конкретной пространственной цепочки определялась экспериментально.
