# Повторный аудит Delo по harness

Дата: 11 сентября 2026 года. Область: последние замечания пользователя, фактический ввод в Win32/WebView2, обе темы, окна, данные и достоверность прежних проверок.

**Последующее обновление по команде пользователя:** обычная копия `app/bin/Delo.exe` заменена проверенной сборкой и запущена без harness. SHA-256 EXE `B239240F1354A4FB94564AC38DE06D167F8D7FB73DEF5EDE2C962B2A2213CB92`; все 12 файлов соответствуют manifest. Подтверждены видимое окно, отвечающий процесс, загрузка main/quick, неизменный файл задач и прежний путь автозапуска. Резервная копия предыдущих файлов и данных: `app/test-output/updates/update-20260911-203007/`; журнал проверки: `verification.json` внутри неё. Старый процесс штатно завершён через пункт «Выход». Установщик в `app/dist` этим обновлением не пересобирался. Ниже сохранены границы первоначального аудита; замечания о необновлённой обычной копии относятся к моменту до этой команды.

При новом запуске записан `owner_error: 1400`; такие же записи присутствовали до обновления. Видимость и загрузка окна подтверждены, но это предупреждение привязки к desktop-host требует отдельного разбора и не засчитывается как PASS оконного слоя.

**Обновление того же дня, вечер:** рендерер возвращён на Windows Graphics Capture + D3D11 + HLSL, рамка захвата снята через `IsBorderRequired(false)`, harness переведён на двухслойную съёмку без захвата экрана. Подробности и измерения — в пункте U01 ниже; прежняя формулировка U01 относилась к промежуточной версии и заменена.

**Вердикт: не все требования закрыты.** В исходниках найдены и исправлены дополнительные дефекты. Полное соответствие Liquid Glass, масштабирование интерфейса и проверка поставки в чистой Windows остаются незавершёнными. Старые результаты установки и сна нельзя автоматически переносить на новую сборку.

## Что обнаружено и исправлено при повторной проверке

1. Собственная глобальная комбинация Delo перехватывалась Windows во время назначения клавиш. На время записи сочетания host освобождает свои RegisterHotKey; после выхода из поля/окна восстанавливает их. Ошибка повторной регистрации показывается пользователю. Физический ввод проверен на кириллической раскладке, включая уже занятое самим Delo сочетание.
2. Позднее CSS-правило тёмной темы перекрывало заливку выполненного кружка. Обычное оформление теперь ограничено незавершёнными задачами; цвета выполнения, просрочки и работы сохраняют приоритет.
3. В узкой корзине две кнопки занимали всю строку, сжимая название задачи до нулевой ширины. Название и действия разделены на строки; кнопки допускают перенос. На ширине окна 320 CSS px текст получает около 256 px.
4. Вложенное подтверждение перезаписывало общий адрес возврата фокуса. Адрес хранится отдельно для каждого диалога. Отмена и закрытие восстанавливают доступный элемент родительского интерфейса.
5. Изменение размеров через SetWindowPos проходило, но перетаскивание угла мышью не работало: WebView2 перехватывал клиентскую область. Восемь зон по краям передают жест в системный resize, сохраняющий ограничения размера и положение. Это проверяется настоящим движением указателя, а не прямой установкой размеров.
6. Более поздняя серия кадров поймала редкое моргание заполненной стрелки: фоновый tick кратко менял `disabled`, хотя состояние задач не менялось. Неизменяющий состояние tick больше не блокирует UI; при настоящем checkpoint сохраняется внешний вид кнопки с черновиком. Отдельный MutationObserver-тест ловит даже переходы короче интервала между кадрами и проверяет реальное сохранение работающего таймера.

Изменения ограничены host, UI и тестами. Данные личного профиля и запущенный обычный `app/bin/Delo.exe` не заменялись. Новая сборка находится в изолированном runtime текущего аудита; существующий установщик 0.1.2 содержит предыдущую сборку.

## Достоверность harness

Обнаруженные ошибки старых проверок не засчитаны как успех приложения:

- Синтетический KeyboardEvent не доказывает регистрацию физической комбинации в Windows. Новый helper использует scan codes и проверяет `isTrusted`.
- Обычный FindWindow мог выбрать запущенную пользовательскую копию. HWND теперь берётся из CDP конкретной сессии; native helper проверяет `--harness=<имя>` и принадлежность точки клика, включая дочерний WebView2.
- Координаты снимка и указателя пересчитываются из CSS px в физические пиксели. Текущая проверка выполнена при масштабе Windows 125%; это не тест всех DPI.
- Для моргания нужны несколько фаз курсора. Серия из 160 кадров включает 8 состояний. В одной из промежуточных серий последний кадр потерял всё окно: пятисекундный watchdog возвращал исключение из захвата до завершения съёмки. В тестовом режиме watchdog увеличен до 15 секунд; `finally` возвращает защиту сразу после съёмки. Негодные кадры не исключаются для получения PASS: серия повторяется. Следующая серия с действующим watchdog обнаружила отдельный настоящий переход цвета стрелки; это привело к исправлению tick/checkpoint, а не к ослаблению допуска сравнения пикселей.
- Тесты ввода использовали старую задачу длиной 4000 символов как подтверждение новой записи. Теперь значение уникально, ожидание включает окончание сохранения.
- Тест меню мог нажимать невидимый элемент за пределами прокрутки. Подготовка приводит видимую область к реальному положению указателя.
- Тесты настроек иногда отправляли форму при отключённой кнопке сохранения. Теперь ожидают доступность кнопки, как при пользовательском взаимодействии.
- Проверка backup больше не подменяет `window.confirm`: она нажимает настоящее подтверждение приложения.

## Повторяемый прогон

Из корня Delo, при закрытых других harness-сессиях:

```powershell
./app/build.ps1 -OutputDirectory ./app/test-output/audit-runtime
./app/tests/run-ui-audit.ps1 -RuntimeDirectory ./app/test-output/audit-runtime
./app/tests/audit-backup.ps1 -RuntimeDirectory ./app/test-output/audit-runtime
node --test app/tests/*.test.mjs
./app/test-store.ps1
./app/test-renderer.ps1
```

Оба сценария создают новое именованное хранилище и отказываются перезаписывать существующее. UI-аудит останавливается при первой неуспешной группе. При выходе ожидается подтверждение сохранения; принудительное завершение не используется. Резервное восстановление намеренно повреждает только созданный этим сценарием профиль.

Локальные JSON, журналы и снимки этой проверки находятся в `app/test-output/sessions/audit-20260911/`; они игнорируются Git и не предназначены для публикации, поскольку снимки могут содержать рабочий стол. `runtime-manifest.json` связывает результаты с проверенными файлами.

## Что ещё не закрыто

- **U01: настоящее преломление — закрыто.** Формулировка выше относилась к промежуточной версии, где GlassRenderer давал Gaussian Blur через Windows Composition Backdrop: смещения фона у кромки не было, tint и блики держались на CSS, а семь проверок effect descriptor преломления не доказывали. Эта версия заменена обратно на Windows Graphics Capture + D3D11 + HLSL (восстановлено из коммита `d8f7083`, включая заморозку материала на время жеста). Преломление подтверждается 9/9 проверками шейдера по фактическим пикселям, среди них «optical edge refracts the blurred source inward» и «Gaussian impulse has no repeated outlines» (`app/test-renderer.ps1`).

  Причина прежней замены — жёлтая рамка захвата, которую Windows рисует вокруг снимаемого монитора. Она снята штатно: `GraphicsCaptureSession.IsBorderRequired(false)`. `RequestAccessAsync(Borderless)` и package identity не потребовались, установщик не затронут. Измерено по цвету рамки в верхней полосе экрана: 1932 жёлтых пикселя до правки, 0 после, 0 при выключенном Delo, 0 на трёх перезапусках финальной сборки.

  Следствие, которое нужно учитывать: окно снова исключает себя из захвата (`WDA_EXCLUDEFROMCAPTURE`) — иначе стекло снимало бы собственный вывод рекурсивно. Виджет не появится ни в одной записи экрана и ни на одном снимке рабочего стола. Поэтому harness больше не фотографирует экран: `screenshot()` собирает кадр из двух слоёв, которые и композятся на экране — материал читается прямо из выходной текстуры GPU (`materialShot` → WIC PNG), документ снимается через CDP `Page.captureScreenshot`, склейка идёт действием `compose`. Это точнее прежнего способа: нет зависимости от z-порядка, чужих окон, фокуса и display affinity.

  **Остаётся открытым — контраст на светлом пёстром фоне.** Замер на настоящем композите поверх красно-белой шахматки: дата в шапке 5.02:1 медиана / 3.71:1 в худшем месте, заголовок задачи 6.63:1, плейсхолдер ввода 3.23:1 / 2.65:1. Для сравнения, на версии с Composition Backdrop те же места давали 2.99 / 2.48, 3.6 / 2.95 и 2.27 / 1.86 — то есть tint шейдера поднял контраст примерно вдвое, но вторичный текст всё ещё не добирает до AA 4.5:1. Метод огрубляет: за текст берётся 97-й перцентиль яркости области, за фон — медиана, поэтому на областях, где текст занимает почти всю площадь, число занижено и не используется. Нужен либо более плотный пол тинта, либо локальная подложка под вторичный текст.
- **Масштабирование интерфейса.** Main изменяется по обеим осям с минимумом 320 × 360 CSS px. Quick имеет фиксированную высоту 83 DIP и изменяется только по горизонтали с минимальной шириной 296 CSS px; старые сохранённые высоты автоматически нормализуются. Отдельный zoom текста/контролов и автоматический переход от маленького main к quick не реализованы.
- **Голосовой ввод.** Значок присутствует и отделён от перетаскивания; распознавание/запись не реализованы.
- **Системные сценарии.** Не закрыты физические несколько мониторов и смена DPI, реальный сон/пробуждение именно пересобранной версии, полный тест с разными фонами и измерением контраста, физический tray click в Explorer. Прежние сообщения пользователя о пробуждении и автозапуске сохранены как наблюдения, а не новый автоматический PASS.
- **Поставка.** Пересобранный runtime не устанавливался поверх обычной копии. Старый installer и его прежние hash/install результаты не удостоверяют новые изменения. Чистая Windows без WebView2 остаётся UNVERIFIED; прежний запуск Sandbox остановился до гостя с RPC `0x800706D9`.

Полная готовность виджета и U01/V12 этим аудитом не объявляются.
