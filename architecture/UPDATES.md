# Обновление Delo внутри приложения

Сценарий для standalone-сборки 0.3.7: «Обновить» → проверка релиза → скачивание с прогрессом → проверка файла → штатное сохранение и выход → установка → повторный запуск. GitHub остаётся хранилищем пакетов; браузер для обновления не открывается. Проверки новых версий остаются добровольными. Store-сборка сохраняет обновление через Microsoft Store.

## Файлы программы и данные

Обновлятор запускает существующий Inno Setup без `/DIR`: установщик использует прежний каталог установки либо свой стандартный `%LOCALAPPDATA%\Programs\Delo`. Исходники и `app/bin` не становятся новой установкой. Задачи, история, настройки, положения окон и черновики остаются в `%LOCALAPPDATA%\Delo`; установщик их не копирует и не удаляет.

Установщик посылает `Delo.RequestExit`. Приложение приостанавливает таймер, сохраняет задачи и черновики и выходит после подтверждения записи. Если сохранение не подтверждено, обновление не должно принудительно завершать виджет. Уже работавший виджет установщик запускает снова после замены файлов.

Существующая запись `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\Delo`, относящаяся к `Delo.exe`, после успешной установки получает новый путь с сохранением аргументов. Отсутствующую запись не создаём. `StartupApproved` не меняем: отключение через Windows остаётся в силе. Чужие и повреждённые команды не переписываем.

## Скачивание и ошибки

Нативный worker заново получает последний стабильный релиз из API `smmisha/Delo`. Выбирается точное имя `Delo-<версия>-windows-x64-setup.exe` с ожидаемыми URL, размером и SHA-256 из `digest` GitHub. Пакеты без корректного digest не запускаются.

Загрузка идёт потоково в отдельный каталог, ограничена 512 МиБ, таймаутами запросов и общим временем 15 минут. Разрешены только HTTPS и серверы GitHub для release assets; каждый редирект проверяется. Проверяются точное число байт и SHA-256. Частичный или повреждённый файл удаляется; перед следующей загрузкой очищаются известные файлы прошлых staging-каталогов без рекурсивного удаления и переходов по junction. Выход пользователя отменяет загрузку. Скачивание не занимает worker сохранения задач.

Кнопка повторного запуска скрыта во время операции. Ошибка оставляет текущую программу работающей и предлагает повторить. После проверки запускается установка без мастера и без перезагрузки Windows. Если установщик завершается до выхода виджета, интерфейс показывает ошибку и пишет код в локальный журнал. Подпись издателя Delo этот механизм не добавляет; источник доверия — HTTPS GitHub и digest релиза.

## Проверки

`app/test-updater.ps1` проверяет выбор пакета, недопустимые версии/URL/размеры/digest, редиректы, потоковый SHA-256 и параметры установщика. `updater-test.exe <новый каталог>` дополнительно проверяет настоящий небольшой GitHub asset, отказ при неверном хеше/размере и отмену без остаточного файла.

`app/tests/audit-updates.mjs` работает с именованным harness, собранным с версией ниже опубликованной. Проверяет настоящую загрузку установщика, прогресс, обе темы, повторное нажатие, отмену выхода с повторной попыткой, смену языка и SHA-256. Harness никогда не запускает скачанный установщик.

`app/tests/test-update-installer.ps1` собирает установщик с отдельными AppId, каталогом, Run key, программной группой и mutex/control. Проверяет перенос автозапуска, выключенное состояние, прежний каталог установки, чужие команды и сохранение контрольной суммы данных. Пользовательскую установку и её автозапуск этот тест не меняет.
