# Delo — результат проверки Windows-слоя

Дата: 10 сентября 2026. Это техническое исследование для Architecture, не завершённая архитектура и не готовый Windows-планировщик.

## Вывод

На целевом ноутбуке подтверждён жизнеспособный механизм **интерактивного дочернего окна существующего desktop-host Explorer**. Виджет остаётся видимым после Win+D, принимает клик и ввод, переключается в topmost и обратно. Для глобального быстрого ввода подходит отдельное верхнеуровневое окно.

Проверено 13 условий, все прошли в финальном прогоне. Машинные данные: [evidence/windows-layer-2026-09-10.json](evidence/windows-layer-2026-09-10.json). Сборка и исходник: [прототип](../prototypes/windows-layer/README.md).

## Окружение и метод

- Windows 11 Pro 25H2, build 26200.9445. Поле ProductName в реестре возвращает старую строку Windows 10 Pro; фактическая проверенная сборка указана явно.
- Основной дисплей 1920×1200, доступная область 1920×1140, DPI 120 (125%).
- SDK .NET отсутствует; установлен .NET runtime 8.0.21. Для проверки использован доступный системный компилятор .NET Framework x64 без установки SDK.
- Создан собственный небольшой C# / WinForms-прототип с Win32-вызовами. Это временная основа измерений, не решение использовать WinForms для визуального приложения.
- Исследование в песочнице не видело Explorer; фактические UI-тесты выполнены в интерактивном рабочем столе пользователя. Манифест требует `asInvoker`, не права администратора.
- Найден уже существующий `Progman` с дочерним `SHELLDLL_DefView`. Не отправлялось сообщение создания WorkerW, не менялись стили окон Explorer и не перезапускалась оболочка.
- Измерялись родитель/стили HWND, попадание мышью в собственное окно, видимость и реальный цвет контрольного пикселя. Просмотрен экранный фрагмент собственного успешно нарисованного окна. Один лишь `IsWindowVisible` не считается доказательством.

## Обнаруженные детали

1. **Поверхность отрисовки терялась при смене родителя.** В ранних прогонах окно имело правильный HWND и hit-test, но на экране оставались обои. Контрольное верхнеуровневое окно рисовалось корректно. Пересоздание layered-поверхности после SetParent устранило проблему в этом прототипе. При переносе на другой renderer этот переход нужно проверить заново.
2. **GetParent не равен проверке верхнеуровневости.** Для owned-popup он возвращает владельца; после отсоединения WS_CHILD необходимо сбросить. Диагностика topmost использует корневой HWND и стиль окна, а не требует нулевой owner.
3. **Win+D не обязательно выглядит как IsIconic=true.** В прогоне обычное окно переставало перекрывать desktop, хотя IsIconic оставался false. Проверка использует фактический hit-test и пиксели.
4. **SendKeys дал некорректную последовательность модификаторов в окне под Explorer.** Проверка ввода переведена на системный SendInput: клик, Ctrl+A и Unicode-текст прошли. Это результат диагностики; ручной ввод пользователя и полный набор сочетаний отдельно не оценивались.
5. **DPI важен при межпроцессном родителе.** Перед созданием окон контекст потока согласован с host. Подтверждён только текущий масштаб, не перенос между мониторами.

## Решения для дальнейшей Architecture

- Изолировать desktop-host adapter от списка задач, репутации и хранилища. Ошибка Explorer не должна уничтожать данные.
- Держать быстрый ввод отдельным верхнеуровневым окном, разделяющим модель задач. Возврат фокуса должен работать и при исчезновении предыдущего окна.
- При смене host/renderer пересоздавать поверхность контролируемо; хранить задачи, черновик и накопленное время вне HWND.
- Добавить наблюдение за потерей host и восстановление окна без бесконечного цикла. Перезапуск Explorer не проверялся на рабочем ноутбуке в этом прогоне.
- Пока не фиксировать WPF, WinUI, Flutter либо web-shell как окончательный стек: прозрачность и оптика могут предъявить другие требования к композиции.

## Что остаётся проверить

1. **Материал:** реальное преломление фона за нативным окном одновременно с desktop-режимом и topmost. В этом прототипе панель непрозрачная, стекло не проверено.
2. **Жизненный цикл:** Explorer restart/crash, сон, блокировка, виртуальные рабочие столы, скрытие значков, перезапуск Delo.
3. **DPI и экраны:** несколько мониторов, разные масштабы, смена основного экрана, восстановление позиции.
4. **Ввод:** Ctrl+Alt+Space для списка, конфликт горячей клавиши, IME, RU/UK/EN, фокус из браузера и других реальных приложений. В этом прогоне фоновым приложением служило собственное обычное тестовое окно.
5. **Ресурсы:** CPU/GPU/RAM в покое и в движении, число кадров, стоимость реального оптического материала. Из данного короткого теста бюджет ресурсов не выводится.
