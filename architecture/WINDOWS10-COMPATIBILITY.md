# Проверка Windows 10 22H2 x64

Дата: 2 октября 2026 года. Целевая система: Windows 10 22H2 x64, сборка 19045.

## Статус

**Основной функциональный прогон на Windows 10 22H2 x64 пройден.** В исходной VM VMware проверен неизменённый EXE из опубликованного MSIX Delo 0.3.1: итоговый отчёт содержит 22 успешные проверки, ошибок 0. Вложенные наборы включают 9 проверок GPU-шейдера, 19 проверок RU/UK/EN, 17 проверок быстрого окна, 9 проверок ввода и 24 проверки меню. Дополнительно прошли 78 JS unit-тестов на точных файлах Store-пакета и 46 UI-проверок. Эти успехи не означают, что весь дополнительный прогон прошёл: в нём есть графические таймауты, таймаут управляющего backup-сценария и незавершённая проверка восстановления того же процесса после сна.

Установлен отдельный тестовый MSIX для Windows 10, подтверждены настоящая package identity, включение его `StartupTask` и фактический автоматический запуск после перезагрузки гостя — 7 из 7 проверок. После проверки автозапуск возвращён в отключённое состояние. Это не установка опубликованного продукта из Microsoft Store. Запись настоящего микрофона прошла до получения текста, однако целевая фраза не совпала; пользователь отдельно сообщил об успешной ручной проверке. Физические мониторы/DPI и полное восстановление после сна остаются непроверенными.

Публичные требования Windows 11 не изменены. На Windows 10 фактически наблюдается жёлтая системная рамка захвата по периметру монитора. Снижение требований опубликованного пакета в этой задаче не выполнялось.

## Реальный прогон

Среда: Windows 10 Домашняя 22H2 x64, `10.0.19045.3803`, интерактивный сеанс 1; VMware SVGA 3D, драйвер `9.17.11.4`; WebView2 Runtime `154.0.4258.48`. VMware Tools установлены пользователем и гостевая Windows перезагружена; Tools Query подтверждает `running: true`, `version: 13349`, `versionStatus: current`.

Сессия `win10-svga-r2`, 2 октября 2026 года: отчёт завершён с `phase: complete`, `passed: true`, все 22 проверки успешны. Проверены запуск основного и быстрого WebView2, создание задачи без дублирования, таймер и завершение задачи, RU/UK/EN, светлая и тёмная темы, ввод и меню. После выхода и повторного запуска сохранились ID, текст, elapsedMs и completedAt тестовой задачи.

Живой renderer до и после перезапуска в основном прогоне: `healthy: true`, `errors: 0`, пустой `error`, размер материала 420×620; счётчики захваченных кадров — 181 и 113, вывод выполнен. `GetWindowDisplayAffinity` возвращает `17` (`WDA_EXCLUDEFROMCAPTURE`). В дополнительном прогоне самоисключение также подтверждено отдельным пиксельным экспериментом, описанным ниже. На итоговом снимке видна жёлтая рамка по периметру рабочего стола.

Первый прогон на базовом видеоадаптере Microsoft не прошёл: renderer фиксировал `0x80070102` и четыре ошибки; вторая копия Delo конфликтовала с первой за стандартные горячие клавиши, что затронуло проверки настроек. После установки Tools и перезагрузки проверена одна копия приложения в новой тестовой сессии. В тестовом клиенте добавлено ожидание полной инициализации документа WebView2 перед выполнением проверок. Код и EXE приложения не менялись. Причина графических таймаутов отдельным экспериментом не изолирована: между прогонами изменились драйвер и количество копий приложения.

Материалы находятся в игнорируемом `app/test-output/windows10-vm/vmware/`:

- `guest-results-win10-svga-r2/compatibility.json` — итоговые результаты и версия среды;
- `guest-results-win10-svga-r2/` — GPU/UI журналы, `native.jsonl` и настройки тестовой сессии;
- `delo-win10-verified.png` — итоговый снимок работающего виджета с системной рамкой;
- `baseline-basic-display-results/` — сохранённые результаты первого неуспешного прогона.

Итоговые журналы получены через Guest API без приостановки Windows. После завершения проверок VM штатно выключена по просьбе пользователя.

## Проверенный пакет

- Файл: `app/dist/Delo-0.3.1-store-x64.msix`.
- SHA-256 пакета: `E7691FBE4DF7A657FED24108EE5939B61CED8409D512B9BF4144E0378FA00C28`.
- Версия извлечённого EXE: `0.3.1`, архитектура x64.
- SHA-256 EXE: `306803C923B0E1351AC325ABCDE91C6B7240FE45B1B5C6E0A59956C8A2CCB99B`.
- PE OperatingSystemVersion и SubsystemVersion: `6.00`; это параметры загрузчика, а не доказательство работоспособности приложения на старых ОС.
- MSIX `TargetDeviceFamily.MinVersion`: `10.0.22000.0`.
- EXE-установщик `app/installer/Delo.iss`: `MinVersion=10.0.22000`.

Оба текущих способа установки опубликованного продукта исключают Windows 10. Для диагностического запуска подготовлена отдельная распакованная копия файлов приложения из того же MSIX, без изменения EXE и требований опубликованного продукта. Она работает без package identity, поэтому не проверяет Store-установку и пакетный автозапуск. Дополнительная локальная MSIX-проверка использует отдельные имя пакета, издателя, подпись и `MinVersion`; её результаты приведены ниже и относятся только к тестовому варианту.

## Найденные ограничения

| Компонент | Вывод по коду и документации |
| --- | --- |
| Захват монитора WGC `CreateForMonitor` | Доступен начиная с Windows 10 1903. На 19045.3803 с VMware SVGA 3D получены живые кадры, renderer healthy и без ошибок. |
| `Direct3D11CaptureFramePool::CreateFreeThreaded` | Доступен начиная с Windows 10 1809. |
| `WDA_EXCLUDEFROMCAPTURE` | Доступен начиная с Windows 10 2004. Режим прочитан как 17, а пиксельная проверка с непрозрачной пурпурной панелью подтвердила отсутствие самозахвата. |
| Захват без цветной рамки `IsBorderRequired` | Минимальная сборка API — 20348, выше целевой 19045. В `app/native/GlassRenderer.cpp` интерфейс `IGraphicsCaptureSession3` запрашивается через `try_as`, отсутствие записывается как `E_NOINTERFACE`, после чего захват продолжается. На Windows 10 фактически наблюдается жёлтая системная рамка вокруг захватываемого монитора. |
| Удаление 1px-рамки окна `DWMWA_BORDER_COLOR` | Поддерживается с Windows 11 22000. В `app/native/Host.cpp` HRESULT не превращается в исключение; запуск и видимый вывод на Windows 10 состоялись. |
| WebView2 | SDK — 1.0.4191.47. На Windows 10 проверен Runtime 154.0.4258.48, оба контроллера, взаимодействие с native host и перезапуск. |
| D3D11 и шейдеры | Renderer создаёт `D3D_DRIVER_TYPE_HARDWARE` и шейдеры модели 5.0. На VMware SVGA 3D прошли 9 проверок шейдера и живой renderer; программного fallback в коде нет. |
| Горячие клавиши, данные и lifecycle | В одной копии проверки регистрации и редактора сочетаний прошли; физические нажатия системных горячих клавиш этим не доказаны. Сохранение задач, таймера, завершения и восстановленного backup после перезапуска проверено. Голос на файлах RU/UK/EN прошёл. Системные события сна/возобновления и сохранённая пауза таймера подтверждены; восстановление renderer и интерфейса в том же процессе после сна не доказано. |

Основное подтверждённое отличие — постоянная системная рамка захвата. Простое снижение `MinVersion` не обеспечивает тот же внешний вид, что на Windows 11. Для публичной поддержки Windows 10 ещё нужны решение по этому отличию, диагностика графических таймаутов и проверка установки/автозапуска будущего публичного пакета.

## Дополнительный прогон 2 октября

На Windows 10 (`osRelease: 10.0.19045`) с Node `v24.14.1` прошли **78 из 78 JS unit-тестов** в 13 наборах; ошибок, пропусков и отменённых тестов — 0. Проверены модель задач и таймеров, дедлайны RU/UK/EN, напоминания, простой, статистика времени, поиск, экспорт/импорт, JS bridge, загрузка, транзакции настроек, политика уведомлений, голосовой UI и источник периодического цикла. Все 17 файлов `core/` и `ui/` в тестовом payload сверены по SHA-256 с соответствующими ZIP-записями исходного Store MSIX, затем хеши файлов и тестов повторно проверены перед запуском в госте. Несовпадений нет; SHA-256 MSIX совпадает с указанным выше. Использованы неизменённые текущие тесты репозитория; два набора, проверяющие тестовый screenshot-helper и классификатор свидетельств, исключены. Это проверки JS-логики в Node, а не отдельное доказательство native host, WebView2 или интеграции с Windows. Отчёт: `unit-tests-guest-summary.json`; происхождение файлов: `../unit-test-payload/provenance.json` относительно каталога VM-журналов.

На том же EXE выполнены ещё 46 UI-проверок: диалоги — 8, архив/корзина и подтверждения удаления — 12, закрепление задач — 12, уменьшение анимации — 5, редактор горячих клавиш — 9. Все прошли. Проверки изменяли только тестовую harness-сессию.

Голосовой движок распознал подготовленные русскую, украинскую и английскую записи за 8,029, 5,334 и 5,168 секунды соответственно. Семь голосовых проверок прошли: три языка, сохранение видимого черновика, отмена настоящего процесса распознавания, размещение элементов быстрого окна и отмена при его скрытии. В том же отчёте восьмая проверка renderer не прошла из-за накопленного `errors: 1`, поэтому общий `passed` голосового набора равен `false`. Начальный запуск голосового теста был некорректен: тест передал имя вне строгого списка `en.wav`, `ru.wav`, `uk.wav`; после исправления теста файлы распознаны без изменений продукта.

Для настоящего микрофона в существующую VM добавлена HDA-звуковая карта после корректного выключения и запуска. Гость обнаружил один вход и один выход; устройство имеет статус `OK`. Действительная запись прошла состояния `recording → transcribing → result`; поле `passed: true` в `extended-voice-microphone.json` подтверждает получение результата. Его текст не совпал с заданной фразой «Купить молоко и позвонить врачу»: в черновик попал другой текст с пометкой музыки. Поэтому точность распознавания целевой фразы не подтверждена. Пользователь отдельно сообщил, что сам проверил голос и всё нормально; это ручной результат пользователя, а не успешная автоматическая проверка точности заданной фразы. Повторная запись отменена по его указанию.

Пиксельное самоисключение: поверх документа Delo добавлена непрозрачная пурпурная панель, занимающая всю область. Документный снимок подтвердил её видимость; счётчик WGC вырос. В GPU-материале до и после панель отсутствует: 15 759 контрольных пикселей, среднее изменение каналов — 0, доля пурпурных пикселей материала — 0, доля панели в документе — 1. Тестовая панель удалена после измерения. Это проверка фактического материала, а не только значения display affinity.

Backup проверен в отдельной новой сессии `win10-backup-final1`: созданы две сохранённые версии, подтверждена предыдущая версия в `tasks.json.bak`, намеренно повреждён только её тестовый `tasks.json`, проверены интерфейс ошибки и подтверждение восстановления, восстановленная задача пережила перезапуск. Все четыре функциональных этапа прошли, включая пять вложенных UI-проверок восстановления. Полный управляющий сценарий завершился таймаутом при последующем запуске основной harness-сессии; приложение затем запустилось. Поэтому общий файл сценария содержит `passed: false` и не выдаётся за полностью успешный прогон.

Подготовлен и установлен отдельный локальный тестовый MSIX `Delo.Win10.CompatibilityTest`, `MinVersion=10.0.19045.0`, с временной тестовой подписью и отдельным издателем. UAC подтверждён пользователем; сертификат добавлен только в `LocalMachine\\TrustedPeople` гостя. Установленный пакет имеет статус `Ok`, хэш его EXE совпадает с опубликованным: `306803C923B0E1351AC325ABCDE91C6B7240FE45B1B5C6E0A59956C8A2CCB99B`. SHA-256 тестового MSIX — `2BE3ED2662C6A5416471C6C29D628B05C1C8AF509D4E4ED096156BC6091695B5`. Это подтверждает локальную MSIX-установку варианта для Windows 10; установка опубликованного продукта из Microsoft Store этим не проверена. Исходный публичный MSIX сохранил прежний хэш и требования Windows 11.

В `package-enable.json` прошли четыре проверки установленного тестового пакета: настоящая package identity и пакетная ветка (`storeManagedUpdates: true`), доступный изначально отключённый `StartupTask`, его включение с чтением `autostart: true` и сохранение тестовой задачи. Использована настоящая пакетная ветка, а не `autostart_simulated` распакованной harness-копии.

Фактический пакетный автозапуск проверен отдельно после перезагрузки гостя: `package-boot-proof.json` содержит **7 из 7 PASS**. Windows загрузилась 2 октября в 03:36:06 по Киеву; один процесс Delo из каталога `WindowsApps` создан в 03:36:37, новые основной и быстрый WebView2 сообщили `main_loaded` и `quick_loaded` в 03:36:39. Процесс запущен автоматически без ручного запуска и без аргументов `--harness` или диагностики. Основное окно видимо и отвечает, сохранённая пакетная задача и `autostart: true` пережили перезагрузку; прочитано внутреннее состояние Windows `State: 2`. Снимок `package-autostart.png` подтверждает видимый виджет с задачей. Результат относится к отдельному локальному тестовому MSIX с требованиями Windows 10; он не проверяет установку публичного пакета из Store и не меняет его `MinVersion=10.0.22000.0`.

Смена разрешения единственного виртуального монитора проверена на том же автоматически запущенном процессе PID 6396: 1280×800, 1920×1080 и возвращение к исходным 1024×768. Каждый отчёт содержит 4 из 4 PASS: запрошенное разрешение установлено, тот же процесс отвечает, основное окно видно и находится в границах экрана, в этой сессии после загрузки не записаны новые `glass_error`. Итого 12 успешных проверок. Снимок `display-1920-1080.png` подтверждает видимый виджет с сохранённой задачей. Во всех трёх режимах обнаружен один монитор и DPI 96; это проверка виртуального разрешения, а не переключения физических мониторов или изменения DPI. Исторические графические таймауты других запусков этими результатами не отменяются.

Короткий тест простоя того же пакетного процесса PID 6396: `package-idle-proof.json`, **2 из 2 PASS**. За 60,16 секунды процесс оставался отвечающим, новых `glass_error` в интервале нет. Измеренная средняя нагрузка самого `Delo.exe` — 7,014% одного vCPU при двух vCPU у гостя; изменение Working Set — −0,02 МиБ. Дочерние WebView2 и Whisper в CPU-метрику не входят. Это минутное наблюдение, а не многочасовой soak, доказательство оптимальности нагрузки или установленная причина её значения.

Сон инициирован внутри Windows через `SetSuspendState(false, false, false)`. Гость поддерживает S1; S3, S4 и Modern Standby недоступны. Получены системные события Kernel-Power 42 и 107 и native-события `power_suspend`/`power_resume` с причиной `system`. VMware преобразовал гостевой сон в приостановку VM; настроенный гостевой wake timer её не возобновил, поэтому выполнено штатное возобновление VMware. На диске задача сохранилась как `paused`, `timerAnchor: null`, `elapsedMs: 2837.4035`. Гостевая Windows после пробуждения показала экран блокировки; автоматический сценарий проверки renderer завершился таймаутом CDP, ожидая ответа в заблокированном сеансе. Его отчёт имеет `phase: error` и `passed: false`. Сохранённая пауза и системные события доказаны, но полное восстановление renderer и интерфейса в том же процессе после сна не подтверждено. Последующий успешный запуск новой копии не заменяет такую проверку.

Обнаружены графические таймауты и после установки VMware SVGA 3D: в двух продолжительных запусках основной renderer записал по одному `0x80070102`, затем снова работал с `healthy: true` и пустым текущим `error`. Накопленный `errors` оставался равен 1, поэтому проверка `errors === 0` в конце дополнительного голосового набора не прошла. Причина этих таймаутов не изолирована; основной короткий прогон 22/22 не доказывает отсутствие проблемы при долгой работе или переходах консоли VM. Публичный код в ходе диагностики не менялся.

После тестов настоящий `StartupTask` возвращён в отключённое состояние: `package-disable.json` содержит 2 из 2 PASS через пакетную ветку, итоговый `autostart: false`. В `package-final-proof.json` прошли 4 из 4 проверки: осталась одна обычная запущенная копия установленного тестового пакета, автозапуск отключён (`startupRegistryState: 0`), временная диагностика удалена, пакетная задача сохранена. Финальный процесс PID 1420 из `WindowsApps` отвечает и работает без аргументов `--harness` или диагностики; слушателя порта 9223 нет, постоянное значение политики диагностики для тестового приложения отсутствует.

Итоговое состояние: по просьбе пользователя исходная VM штатно выключена, VMware закрыт для освобождения ресурсов ноутбука. Перед выключением восстановлено разрешение 1024×768. Отдельный тестовый пакет и его данные сохранены в VM; снимок `package-final.png` показывает виджет до выключения. Временный сертификат со сроком действия два дня остаётся только в доверенном хранилище гостя; доверие хоста не менялось. Физические нажатия системных горячих клавиш и Win+D в этом прогоне подтверждения не получили и остаются **UNVERIFIED**. Полный дополнительный прогон не объявляется успешным из-за описанных выше таймаутов и незавершённой проверки восстановления после сна.

### Установка VMware и Windows

VMware Workstation Pro 26H1u1, версия 26.0.1 build 25688693, установлен штатным установщиком; MSI журнал подтверждает успешное завершение, код возврата 0, перезагрузка хоста не потребовалась. Регистрация Broadcom не выполнялась. EXE получен из публичного зеркала, до запуска проверены действительная Authenticode-подпись Broadcom Inc и SHA-256 `3D775C3C2153600EEF4642F95D519A514BA7E861400BDA2598352BFF792DB473`.

Для новой VM использованы 2 vCPU, 3072 МиБ RAM, растущий диск 60 ГиБ, BIOS, NAT, VMware SVGA с 3D и 256 МиБ графической памяти. Hyper-V/VBS и настройки безопасности хоста не изменялись, side-channel mitigations VMware оставлены включёнными. Файлы пользователя и общие папки в VM не подключались.

Начальная загрузка с носителя ответов не запустила Windows Setup; порядок исправлен на `cdrom,hdd`. Затем Setup сообщил, что не удалось применить `DiskConfiguration`. После единственной замены контроллера LSI Logic Parallel (`lsilogic`) на LSI Logic SAS (`lsisas1068`) прежний файл ответов успешно подготовил диск и установка продолжилась. Наблюдались подготовка файлов, установка компонентов, загрузка с диска, первоначальная настройка и рабочий стол Windows 10.

ISO VMware Tools этой версии содержит `setup.exe`, а не `setup64.exe`. Извлечённый из исходной VM журнал `C:\DeloTest\setup.log` подтверждает, что файлы Delo и тестовых инструментов скопированы, после чего первый сценарий остановился с `VMware Tools media not found`: он искал неверное имя установщика. Подготовленный сценарий исправлен и подключён новый тестовый DVD `delo-test-payload-v2.iso`, но одноразовый FirstLogonCommands уже завершился и от замены DVD повторно не запускается. Переустановка Windows для исправления этого шага не требуется.

Дополнительная VM `Delo-Win10-22H2-test` была ошибочно запущена для повторения установки; пользователь остановил её. Работа продолжена в исходной уже установленной `Delo-Win10-22H2`.

До ручной установки штатный Tools Query возвращал `version: 0`, `running: false`, `versionStatus: no_tools`. Команда Tools Install только подключила установочный носитель. Пользователь сначала запустил Delo с тестового DVD и затем готовый прогон; этот прогон на базовом видеоадаптере не прошёл. Нажатия инструмента через консоль не дали результата, поэтому мастер Tools завершён пользователем. После гостевой перезагрузки Tools готовы и повторный прогон выполнен автоматически через Guest API.

Версия 19045.3803/22H2, WebView2, основной функциональный прогон, живой захват и фактическая жёлтая рамка подтверждены журналами и снимками. Исходный FirstLogonCommands как единый сценарий не прошёл: Tools установлены вручную, тесты запущены отдельно. Скриншоты и журналы хранятся в игнорируемом `app/test-output/windows10-vm/vmware/`.
