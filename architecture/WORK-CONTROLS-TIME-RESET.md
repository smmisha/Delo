## 2. Текущая реализация

В строке задачи `.timer` запускает отсчёт или ставит его на паузу. В `.work-strip` отдельно находятся текст состояния, накопленное время, пауза/продолжение работы без таймера и «Стоп».

Два Play в режиме без таймера имеют разный смысл: верхний начинает измерять время (`start`), нижний продолжает без измерения (`work`). После удаления визуального дубля оба режима должны остаться доступны.

П16 уже ограничивает рабочий фокус одной задачей: `running` — с таймером, `working` — без него. Пауза без таймера определяется через `untimedPause` и при продолжении не должна включать отсчёт.

Время хранится в `elapsedMs` и `intervals`. Старое накопление без интервалов учитывается как «До начала учёта». Сброс только `elapsedMs` оставит неверную статистику.

## 3. U09 — единая кнопка работы без таймера

Вместо пассивной подписи и отдельной кнопки в полосе используется одна текстовая кнопка. Видимая подпись обозначает следующее действие:

| Состояние | Кнопка в полосе | Команда | Таймер в основной строке |
| --- | --- | --- | --- |
| Без таймера, в работе | ⏸ Пауза | `pause` | Скрыт |
| Пауза без таймера | ▶ Продолжить | `work`, без отсчёта | Скрыт |
| Таймер идёт | Прежняя подпись состояния | — | ⏸ Пауза таймера |
| Таймер на паузе | Прежняя подпись состояния | — | ▶ Продолжить таймер |
| Нейтральная незавершённая | Полоса по прежним правилам | — | ▶ Запустить таймер |
| Завершённая | Без новых рабочих действий | — | Прежнее недоступное состояние |

Символы в таблице обозначают существующие SVG-значки приложения. После «Продолжить» та же кнопка становится «Пауза»; после «Пауза» — «Продолжить». Повторяющей подписи и второй кнопки того же действия рядом нет.

Для режима без таймера явный переход к измерению переносится в `⋯ → Запустить таймер`. Существующий переход к работе без таймера сохраняется. «Стоп» остаётся отдельным действием: заканчивает подход и сохраняет накопление, не выполняя задачу.

Ограничения:

- Сохранить числовое время, срок, завершение, «Стоп» и меню. Отдельно не менять правило показа нулевых часов.
- Колонка `⋯` остаётся согласованной между строками; скрытая кнопка не оставляет невидимую область нажатия.
- Доступное имя поясняет режим: «Приостановить работу без таймера» / «Продолжить без таймера». Подсказка дополняет, но не заменяет клавиатурную доступность.
- Область управления от 44 CSS px, Tab/Enter/Space, сохранение фокуса после перерисовки, обе темы, RU/UK/EN, reduced-motion, длинный текст и ширина окна от 320 CSS px.
- F05/П16 и режим продолжения глобальной горячей клавишей сохраняются. Взятие другой задачи в работу приостанавливает прежнюю. П15 сохраняет защиту от перестановки строки под указателем.

## 4. F07 — обнуление времени

### Доступ и подтверждение

Пункт `⋯ → Обнулить время…` доступен для активных задач с накоплением больше нуля, включая завершённые в сегодняшней группе. Для идущего таймера учитывается ещё не записанный отрезок через `elapsed(task, mono())`.

При нуле пункт недоступен. Архив и корзина новых кнопок в этом цикле не получают: сначала используется существующее восстановление задачи. Массовый сброс, вычитание длительности и коррекция отдельного дня/недели исключены.

Использовать существующее `askConfirmation`, безопасный начальный фокус на «Отмена», Escape и возврат фокуса. Текст:

> Обнулить всё время этой задачи? Оно также будет удалено из статистики. Это действие нельзя отменить.

Для идущего таймера дополнительно объяснить его приостановку и назвать действие «Обнулить и приостановить». Иначе — «Обнулить время». До подтверждения таймер работает как обычно. Команда очищает всё накопление на момент исполнения, включая время ожидания в диалоге.

Открытие диалога, отмена и Escape ничего не сбрасывают. Новая общая система undo в этот цикл не входит.

### Доменная команда `resetTime`

Команда проходит через модель и существующее подтверждённое сохранение, без прямой правки JSON из UI.

| До сброса | После подтверждения |
| --- | --- |
| Идущий таймер | Таймер на паузе, время 0; сам не возобновляется |
| Пауза таймера | Та же пауза, время 0 |
| Работа без таймера | Та же работа без таймера, прежнее накопление 0 |
| Пауза без таймера | Та же пауза, продолжение без отсчёта |
| Нейтральная задача | Нейтральная задача, время 0 |
| Завершённая активная задача | Остаётся завершённой, время 0 |

Постусловия:

1. `elapsedMs = 0`, `intervals = []`, `timerAnchor = null`. Старый живой отрезок не дописывается обратно при checkpoint.
2. Удаляется устаревший вопрос `idle`; запоздавший ответ на него не вычитает время снова.
3. Сохраняется смысл `untimedPause`, согласованность `untimedState` с новым накоплением и совместимость старой пометки `untimed` без снимка. Пауза без таймера не превращается в паузу секундомера.
4. Пауза идущего таймера использует обычный причинный порядок касаний. В других состояниях административный сброс не имитирует новое начало работы.
5. Сброс не меняет ID, название, срок, закреп, выполнение, награду, штрафы и историю репутации; не приостанавливает другие задачи. Штатная обработка сроков/архивирования сохраняет прежние правила.
6. Вклад выбранной задачи в «Сегодня», «Неделя» и «До начала учёта» становится нулевым. Вклад остальных задач сохраняется; отрицательного времени нет.
7. Ноль и режим переживают перезапуск и экспорт/импорт. Следующий запуск измерения начинает новый подход с нуля.
8. Повторная команда при нуле не создаёт побочных событий. Пока запрос выполняется, повторное подтверждение заблокировано.

Текущих полей достаточно: новая `schemaVersion`, миграция, журнал ручных поправок и изменения renderer не планируются. Native Store остаётся существующим каналом записи с revision и backup.

### Ошибки и конфликты

Успешный сброс показывается после подтверждения записи. При ошибке нельзя оставлять ложный ноль: действуют существующие ошибка и resync. После timeout хост может закончить запись позднее — перед повторным действием сначала перечитать состояние.

При удалении/архивировании цели, импорте или конфликте revision не переигрывать необратимую команду автоматически по новым данным. Перечитать состояние; следующее явное действие требует нового подтверждения. Проверить автоматический retry в `transaction`/`attemptTransaction` и локально отключить его для этого сценария, не меняя поведение остальных команд.

## 7. Изменения и модель реализации

Ожидаемые места: `app/core/model.mjs`, тесты модели/статистики в `app/tests`, `app/ui/app.mjs`, `app/ui/app.css`, `app/ui/index.html`, `app/ui/i18n.mjs` и узкое расширение существующего live harness. Native Store, формат данных и графический движок переиспользуются. Окончательный diff определяется после R0/R1.

Для составления пользователь выбрал GPT-6.1 Sol + Max; фактическое переключение настроек этого чата не подтверждено.

Для реализации рекомендуется GPT-6.1 Sol + High, если этот уровень доступен в Desktop: здесь связаны UI, время, статистика, режим продолжения и подтверждённая запись. Max полезен при неоднозначном восстановлении или сложном конфликте записи. Это рекомендация, не заявление о текущей настройке или гарантированной доступности effort в picker. Весь сценарий лучше вести одним исполнителем; отдельно ограниченные переводы/оформление можно поручить Luna после фиксации контракта. Модель и скорость автоматически не переключаются.
