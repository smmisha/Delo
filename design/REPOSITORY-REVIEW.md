# Delo — оценка семи репозиториев

Дата: 10 сентября 2026. Проверены README, доступная документация и выборочные исходники. Библиотеки не установлены и не собраны; заявления авторов о производительности не являются нашими измерениями. Это исследование для SPEC/Architecture, а не решение сменить текущий дизайн Claude или стек.

## Выбор для следующего этапа

1. Сохранить текущий дизайн и работающий renderer как базу сравнения.
2. Для уточнения UX использовать отдельные справки `apple-skills`, не устанавливать всё автоматически.
3. При необходимости улучшить веб-материал сначала проверить `liquidGL` на изолированной поверхности. Если архитектура выберет React — сравнить `rdev` и `samasante`. Если Flutter — отдельно проверить `liquid_glass_widgets` на Windows.
4. До включения зависимости зафиксировать версию/commit, проверить её лицензию и лицензии включённых компонентов, затем измерить запуск, память, GPU/CPU в покое, движение и fallback на целевом ноутбуке.

Вывод по области применения: изученные пакеты сами по себе не закрывают весь контракт Windows-виджета — Win+D, desktop-слой, topmost, трей, системные горячие клавиши и источник пикселей за окном. Эффект внутри страницы или Flutter-сцены не доказывает преломление других окон Windows. Это отдельный технический прототип на этапе Architecture.

## Готовность к SPEC

Начинать SPEC можно сейчас. Подтверждены основная компоновка, ввод, редактирование, сроки как необязательное поле, состояния задач, таймер, обе темы, языки, архив, корзина и направление анимаций. Точная библиотека не нужна для формулировки требований.

Пользователь подтвердил: дата с необязательным временем (без времени — до конца дня); баллы +5 за обычное выполнение, +2 за позднее, −2 при просрочке и ещё −1 через 7 дней; автоматическая очистка корзины через 30 дней после удаления. При написании SPEC также формализовать изменение срока после штрафа, поведение таймера во сне/после перезапуска и восстановление из архива. Предложенные дополнительные правила не отмечать утверждёнными без ответа пользователя.

Порядок дальше: SPEC → проверяемый Windows-прототип сложных интеграций и ARCHITECTURE → актуальный ROADMAP → небольшие TASKS → реализация. Старый ROADMAP остаётся предварительным: содержащаяся там уступка «точное воспроизведение материалов не является критерием» не должна отменять более поздний запрос пользователя на настоящее видимое преломление.

## Модель

По сообщению пользователя текущий выбор — GPT-6 Astra High. Для SPEC и выбора Windows-архитектуры сохранить его: ошибки сейчас затрагивают много последующей реализации. Max/Ultra не требуются без конкретной трудности. Для обычных ограниченных задач реализации рекомендация — GPT-5.6 Sol High; для небольших проверяемых исправлений можно выбирать Terra Medium. Это оценка пригодности по `codex-model-routing`, не результат сравнительного бенчмарка и не заявление о переключении текущей модели.
