# Delo — explicit GPU glass probe

## Проверки устойчивости и нагрузки

`run-stability.ps1 -Profile` выполняет короткие замеры покоя, движения и возврата в покой. Лог содержит число обновлений источника и суммарное время копирования, проверки изменений и отрисовки/Present. Контроль движения требует от 29 до 31 обновления источника в секунду и не менее 28 отрисовок/с. Флаг нельзя сочетать с ManualSleep или Soak. Планирование кадров использует монотонные точные часы и локальные high-resolution waitable timers; таймеры освобождаются через RAII. Неизменившийся кадр не запускает ограничение частоты заново.

`build-stability.ps1` собирает стенд, `run-stability.ps1` запускает автоматические проверки восстановления и короткие замеры. `run-stability.ps1 -ManualSleep` ждёт ручного сна и пробуждения до 10 минут. `run-stability.ps1 -Soak` выполняет пять минут замеров в одном процессе: десять интервалов по 30 секунд с чередованием движения и покоя, плюс прогрев и проверки. Эти два флага несовместимы.

Во время прогона оставьте ноутбук бодрствующим (кроме ManualSleep), не закрывайте контрольную сетку и окно стекла. После завершения окна закрываются автоматически. Требуется доступ к интерактивному рабочему столу, запуск из песочницы может не поддерживать захват.

Soak сохраняет показатели CPU, памяти, кадров и дескрипторов каждые 30 секунд. Проверяет отсутствие неожиданных пересозданий ресурсов, работу renderer, отсутствие отрисовок в покое и сохранность оптики в конце. Пороги роста относительно прогретого процесса: 32 МиБ private memory и 20 дескрипторов. Это диагностические пороги, не доказательство отсутствия медленной утечки. Результаты и ограничения: [STABILITY.md](../../architecture/STABILITY.md).

**Работает в проверенной конфигурации:** отдельный HLSL-шейдер преломляет GPU-текстуру и кадр собственного внешнего HWND. Это исследовательский прототип, не интерфейс планировщика и не окончательный материал.

## Запуск

Из этой папки в PowerShell:

```powershell
./build.ps1
./run.ps1
```

Сборка использует уже установленные MSVC 14.50.35717 и Windows SDK 10.0.26100.0; пути указаны в `build.ps1`. Сторонние пакеты и новый SDK не устанавливаются. Требуются Windows с Windows Graphics Capture, поддержкой CreateForWindow и D3D11 hardware device. Фактически проверено на Windows 11 25H2 x64, AMD Radeon 610M.

`run.ps1` запускает два коротких процесса. `--internal` генерирует сетку отдельным GPU-проходом. `--external` захватывает только собственное окно с GDI-сеткой через публичный Windows Graphics Capture. Окно результата временно перекрывает источник для проверки отсутствия самозахвата. Предыдущий фокус восстанавливается, созданные окна закрываются. Не переключайте окна в эти несколько секунд: перекрытие чужим окном делает проверку отображения недостоверной и приводит к провалу соответствующей проверки.

Результаты: `bin/internal-<tick>/checks.jsonl`, `bin/external-<tick>/checks.jsonl`, BMP исходной текстуры, линзы и обновлённого кадра. Ненулевой код завершения означает ошибку/непройденную проверку. Шейдер загружается из `Glass.hlsl` относительно EXE; файл должен оставаться рядом с папкой `bin`.

## Механизм

```text
GPU-generated grid ──────────────────────────────┐
                                                ↓
Own HWND → Windows Graphics Capture → D3D11 texture → HLSL lens
                                                        ↓
                                              premultiplied BGRA
                                                        ↓
                                      DirectComposition swap chain → own HWND
```

Шейдер использует расстояние до округлённого прямоугольника и направленное смещение выборки, усиливающееся у кромки. Это диагностическая модель линзы, не физически точная оптика. Центральная область не смещается. Альфа скруглений передаётся в DirectComposition. Текст, блики, рассеяние и финальный tint ещё не добавлены.

Кадры WGC копируются и обрабатываются на GPU; CPU readback нужен только для проверок и сохранения свидетельств. Перехват функций, изменение памяти чужих процессов, приватные API App SDK и экранные скриншоты как источник эффекта не используются. Пять точек внутри непрозрачной части собственного окна считываются с экрана исключительно для проверки фактического вывода.

В тесте проверяются два состояния движущейся сетки в каждой теме. Это проверка обновления источника, **не** измерение стабильной частоты кадров, задержки или энергопотребления. Непрерывный цикл отображения по событию нового кадра будет отдельной работой.

## Границы результата

39/39 проверок: 16 для внутренней текстуры, 23 для отдельного HWND. [Отчёт и свидетельства](../../architecture/GPU-GLASS.md).

Захват конкретного HWND не равен захвату произвольного рабочего стола за виджетом. Самозахват исключён в проверенном оконном сценарии; monitor capture, desktop/topmost, Win+D, DPI-переходы, смена размера, потеря устройства и Explorer restart с этим renderer ещё не проверены. Ошибки и неожиданный размер источника завершают пробник, а не маскируются успешным результатом.

Исходники `Probe.cpp` и `Glass.hlsl` написаны для этого эксперимента; код LiquidGlassWinUI не переносился. Документация API приведена в отчёте. Проект не публиковался и не является установщиком.

## Дополнительный monitor-пробник

Реальный фон монитора проверен отдельно: 25/25. Запуск: build-monitor.ps1, затем run-monitor.ps1. Новый MonitorProbe.cpp переиспользует GPU-код и шейдер. WDA_EXCLUDEFROMCAPTURE исключает собственное верхнеуровневое окно, а цикл проверки не запускается при провале исключения. Сохраняется только участок 400×300; пользовательские снимки остаются в bin. [Результаты и ограничения](../../architecture/MONITOR-GLASS.md). Привязка к Explorer, Win+D и ввод с monitor capture пока не проверены.

## Desktop / topmost с материалом

Рабочий owner-вариант: build-modes.ps1, затем run-modes.ps1. Два цикла, реальный Win+D и ввод в собственное окно; во время прогона не переключать окна и не удерживать модификаторы. 49 проверок прошли. Окно материала остаётся top-level, владельцем в desktop-режиме назначается Explorer; диагностический WS_CHILD-вариант (--child) ожидаемо не проходит WDA. [Подробности, изображения и ограничения](../../architecture/GLASS-WINDOW-MODES.md).
