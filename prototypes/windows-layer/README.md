# Delo — проверка Windows-слоя

Изолированный диагностический прототип. Проверяет поведение окна и ввода; не содержит задач, хранилища или Liquid Glass. Использует C# / WinForms / Win32 и встроенный компилятор .NET Framework x64. Это не выбор окончательного стека приложения.

## Результат

10 сентября 2026: **13 из 13 проверок прошли**, код выхода 0. Windows 11 Pro 25H2, сборка 26200.9445, монитор 1920×1200, DPI 120 (125%). Подробности: [WINDOWS-LAYER.md](../../architecture/WINDOWS-LAYER.md), [машинный отчёт](../../architecture/evidence/windows-layer-2026-09-10.json).

## Сборка и запуск

Из PowerShell в этом каталоге:

```powershell
./build.ps1
./bin/Delo.LayerProbe.exe --self-test
```

Самопроверка показывает два собственных окна, дважды посылает Win+D, переключает desktop/topmost, регистрирует Ctrl+Alt+N, проверяет ввод и завершает процесс. Во время короткого прогона не переключайте окна и не нажимайте клавиши. Если Ctrl/Alt/Shift/Win уже удерживаются, ввод отменяется. Тест не перезапускает Explorer, не меняет обои/настройки и не записывает настоящие задачи.

Без `--self-test` остаётся интерактивное диагностическое окно с кнопками Desktop / Topmost / Exit. Ctrl+Alt+N вызывает тестовый ввод; введённый текст не сохраняется как задача. Сочетание освобождается при выходе. Для проверки необходим обычный интерактивный рабочий стол пользователя; изолированный desktop песочницы не видит Explorer.

Результат записывается в `bin/results.json`. Ошибка проверки даёт код 1, ошибка запуска — 2. Изображения в `bin` показывают диагностическое окно; программа получает небольшой экранный фрагмент только в точке, где hit-test обнаружил собственное окно. При неуспешной отрисовке такой фрагмент может содержать фон рабочего стола, поэтому `bin` исключён из публикации. Не публикуйте диагностические картинки автоматически.

## Ограничения

Четвёртый эксперимент — `Delo.RefractionProbe.exe`, сборка `./build-refraction.ps1`. [Отчёт о преломлении](../../architecture/REFRACTION.md). Проверяет цветовой источник, внутреннюю контрольную сетку и реальный внешний фон в двух темах / режимах. При успехе всех оптических сценариев автоматически запускает подготовленную проверку перепривязки и ввода. Последний прогон завершился кодом 1: преломление внешней сетки не работает, поэтому ветка ввода не выполнялась. Журнал — `bin/refraction.jsonl`; снимки — в `bin`. Запуск временно переключает Win+D и автоматически закрывает собственные окна.

Третий эксперимент — чистый Win32/C++/WinRT `Delo.NativeWindowProbe.exe`, сборка `./build-native-window.ps1`. [Отчёт](../../architecture/NATIVE-WINDOW.md). При запуске автоматически создаёт временные окна, для двух desktop-конфигураций выполняет Win+D с обратным переключением и завершает процесс; журнал — `bin/native-window.jsonl`. Последний прогон с Saturation-контролем: 20/25, код 1. Все три проверки обработки внешнего фона прошли; пять ошибок относятся к HostBackdrop и DWM-настройкам дочерних окон. Блокировка по кредитам устранена.

Второй эксперимент, `Delo.HostBackdropProbe.exe`, описан в [NATIVE-MATERIAL.md](../../architecture/NATIVE-MATERIAL.md). Сборка: сначала `./build-effect.ps1`, затем `./build-host-backdrop.ps1`. Нужны указанные в скриптах локальные MSVC/Windows SDK. Последний прогон этого эксперимента **не прошёл** (код 1); успешные 13 проверок выше относятся только к `Delo.LayerProbe.exe`.

- Это короткий тест на одной установленной версии Windows, не обещание совместимости всех сборок.
- Слой Explorer не является отдельным официальным Widget SDK: нужна обработка смены/потери HWND и проверка после обновлений Windows.
- Нет Liquid Glass, трея, сохранения позиции, восстановления после падения Explorer, обработки сна или полноценного DPI-переноса между мониторами.
- Кнопки и цветная панель служат измерению; дизайн Delo остаётся в `design/index.html`.
- Реализация оригинальная. Lively изучался как референс поведения оболочки; его код и библиотеки в прототип не включены. Ссылки приведены в отчёте.
